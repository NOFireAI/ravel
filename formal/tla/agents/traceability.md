# Traceability: agent protocol actions and invariants to their Rust source

Each row maps a TLA+ action or named property of the three agent models
(`AgentProtocol.tla`, `AgentEffects.tla` and `AgentIntegrated.tla`, with their
`MC*` wrappers) to the agent behavior it pins, in the words of ADR-3331,
to the Rust symbol that implements that behavior, and to the test that
exercises it (ADR-3331 decision 13). `scripts/check-tla.sh traceability -a
agents` resolves the Rust references: a reference is
`crates/<path>.rs::Sym1::Sym2...`, and the check requires the file to exist and
every `::`-separated symbol to appear in it. A reference to a `.tla` file is
rejected: a traceability row cites the implementation, not the model. The
"new test needed" column names a gap where no test pins the modeled clause
yet, or `none` when an existing test covers it.

The table covers what `ravel-agents-core` (the pure HEAD kernel) and
`ravel-agents-store` (the publication skeleton over object storage) implement
today. A row whose model action spans both cites the kernel transition and the
store step side by side. A row with no module named in its first cell is an
`AgentProtocol` row; the effect journal rows name `AgentEffects` and
`AgentIntegrated` where the action is theirs. The models' runtime side (the
lease table, the worker protocol, crash recovery, the effect runner, the
wake-hint sweep) and their liveness properties have no Rust yet; they are listed as prose under "Design rows (not yet built)"
below, with the ticket that builds each.

## Design rows (not yet built)

These model actions and properties describe parts of the coordinator in
`ravel-agents-runtime` that are not built yet. Each row joins the table
above in the task that builds its symbol.

- `Takeover` and `BeginTurn` as the runtime drives them: activation through the
  runtime lease table and the worker protocol that issues the kernel's
  takeover and begin commands. Built by T9 (#3343) as the coordinator in
  `ravel-agents-runtime`; the rows will cite its ownership module (the lease
  table and takeover) and its dispatch module (BeginTurn by `accept_seq`).
- `WorkerCrash` and the resumed turn under the next owner: a worker that dies
  mid-turn loses its lease, and the next owner's takeover resumes the active
  turn. The kernel's resume path (`Kernel::begin_turn` answering
  `TurnResumed`) exists; the crash detection and re-dispatch are T9 (#3343),
  citing the coordinator's lease expiry and takeover path, and the end-to-end
  crash test is T13 (#3346) in `ravel-agents-sim`.
- Liveness: `InputEventuallyResolved` and `DueTimerEventuallyDelivered` hold
  only under the coordinator's fairness (dispatch, retry and the sweep). The
  sweep has landed (`crates/ravel-agents-runtime/src/sweep.rs::Coordinator::sweep_once`):
  a bounded pass resumes from a cursor, so every agent it can list is read
  within a bounded number of passes
  (`crates/ravel-agents-runtime/src/sweep/tests.rs::a_bounded_pass_walks_the_directory_in_list_order_across_passes`,
  `crates/ravel-agents-runtime/src/sweep/tests.rs::the_wake_half_reads_its_share_of_the_get_cap_and_resumes_across_passes`).
  The rows wait for simulation schedules that drive a resolved input and a
  delivered timer through the production crates; the T13 (#3346) drivers
  schedule no timers yet. Model difference: the model reaches a timer only
  through its hint and assumes the hint write under `Fairness` (the
  HEAD-listing half of the sweep is not modelled). The code's backstop for
  a lost hint is the `_dir` listing, not a HEAD listing (ADR-3331, the
  directory amendment to decision 8). The listing is complete because a
  create writes the entry before HEAD and fails without it
  (`crates/ravel-agents-store/src/tests.rs::a_create_whose_dir_entry_fails_writes_no_head`),
  and a hint-reached agent whose entry went missing gets it back
  (`crates/ravel-agents-runtime/src/sweep/tests.rs::a_hint_reached_agent_gets_its_missing_dir_entry_back`);
  the `sweep` module docs state the bound.
- The effect runner: T14 built the coordinator's step and effect path
  (`Coordinator::run_step`, `record_result`, `reconcile_attach`,
  `reconcile_authorize` in `crates/ravel-agents-runtime/src/effects.rs`),
  and the rows above cite it where a model rule rests on it. Still without
  a row: `Dispatch`, `Respond`, `LoseResponse` and `Recover` as provider
  steps (the model's provider is an assumption, not code), and the
  remaining guards the README lists under "Differences from the kernel".
- `SweepRead` and `SweepFire` in `AgentIntegrated`: the sweep reads HEAD
  and fires a due generation with a CAS on the version it read, and a
  failed CAS leaves HEAD alone. The code is
  `crates/ravel-agents-runtime/src/sweep.rs::Coordinator::sweep_once`, which
  reads HEAD and fires through `timers.rs::fire_due`.
- Liveness in the two new models: `InputSettledOrEffectBlocked`
  (`AgentEffects`, `AgentIntegrated`) and `EnqueueEventuallyAnswered`
  (`AgentIntegrated`) hold under the runner's and the sweep's fairness. The
  runner exists (`Coordinator::run_step`) but no test cited here pins either
  property; the sweep half is `Coordinator::sweep_once`.
