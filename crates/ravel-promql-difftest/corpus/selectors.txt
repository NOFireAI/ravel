# -0.0 is deliberately excluded from this corpus, not merely untested: the
# pinned Prometheus binary renders this dataset's -0.0 sample as "0"
# (verified against v3.13.1), so it does not preserve the sign of zero
# through its own storage/query path, while Ravel's comparator treats
# -0.0 as bit-significant by design (src/comparator.rs's own header
# comment; CLAUDE.md's float-comparison testing pattern). Matching
# Prometheus here
# would mean Ravel deliberately discarding a bit it currently preserves
# correctly. This is a real, accepted engine-behavior divergence, not a
# corpus mistake.
