- **The memory gate no longer closes on a dip in host available memory
  shorter than 300 ms.** The gate closed on one sample below its close floor,
  so a dip lasting well under the 2 s a host monitor samples at refused work
  for as long as the gate stayed shut: in the acceptance run one concurrent
  phase scored a 0.379 error ratio while the host never showed less than
  1.22 GB available (issue #2838). The `ravel-memory-gate` sampler now closes
  the gate only after `--memory-gate-close-after-samples` consecutive samples
  below `--memory-gate-min-available-bytes` (default 3, accepted 1 to 100; at
  the default 100 ms interval a dip must last at least 300 ms to close it),
  and reopens it on the first sample at or above the floor. The value 1 is
  the previous behaviour. The purge decision is unchanged. Every sample below
  the floor counts on the new `ravel_memory_gate_samples_below_floor_total`,
  whether or not it closed the gate, and `ravel_memory_gate_available_bytes`
  shows the dip while the gate stays open. The `memory gate resolved` line
  stamps `close_after_samples`.
