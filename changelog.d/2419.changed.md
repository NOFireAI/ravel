- **The derived per-query SQL memory pool is now the tenant's share**
  (issue #2419). `--sql-max-query-bytes`, unset, now derives at 50% of
  `MemTotal`, equal to `--sql-tenant-max-bytes` (16,106,127,360 on the
  16-core, 30 GiB reference host, up from 8,053,063,680), instead of 25%: a
  lone statement may now reserve the tenant's whole SQL share. This is not an
  added reservation: the per-query pool nests inside the per-tenant pool as
  before, so the per-tenant ceiling still refuses the byte that would carry
  one tenant past 50% regardless of how many statements share it, and
  concurrency is bounded exactly as before. An explicit `--sql-max-query-bytes`
  still wins over the derivation and is still clamped to the tenant ceiling;
  an operator who wants the old four-way split across concurrent statements
  sets it to a quarter of the tenant ceiling.
