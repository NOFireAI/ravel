- **A metrics fetch over a large compacted segment no longer reserves gap
  bytes past its share of the fetch memory budget** (#3818). Coalescing within
  the 64 KiB gap, and on L0 objects bridging down to 4 page runs, could join
  the small pages a query selected into one run spanning most of a segment,
  and the whole run was reserved against the fetch budget, so a query whose
  needed bytes fit could be refused with `fetch memory exhausted`. Neither
  step now joins needed ranges into a run longer than the budget's limit
  divided by the GET concurrency, or 8 MiB when that share is smaller; a
  single needed range longer than that is still fetched whole in one GET
  (`coalescing_never_builds_a_run_past_the_fetch_share`,
  `bridging_never_builds_a_run_past_the_fetch_share`,
  `the_cap_never_splits_a_needed_range`). An L0 fetch of an object longer
  than that cap, so never one of 8 MiB or less, can now issue more than 4
  page GETs (`max_run_len_is_the_per_get_share_with_a_floor`).
