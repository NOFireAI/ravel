- **CPU-aware ingest admission** (ADR-3718, issue #3720). A background
  detector samples the process's own CPU use and the ingest routers'
  deferred-flush-trigger rate every 100 ms; while the node is saturated (CPU
  at or above `--ingest-cpu-shed-threshold`, default 0.95, with at least one
  deferred flush trigger in the last second) it raises a shed fraction `p`,
  capped at `--ingest-cpu-shed-max` (default 0.9). Every OTLP and Remote
  Write request then draws once against `p` at the head, right after the
  in-flight permit and before the tenant is resolved, so a saturated node
  sheds before doing any tenant work for a request it will refuse. Refused
  requests get 429 with `Retry-After: 1` on HTTP and `RESOURCE_EXHAUSTED` on
  gRPC, counted on the new `ravel_ingest_cpu_shed_total{mode}`; the current
  `p` exports as the gauge `ravel_ingest_cpu_shed_fraction{mode}`.
  `--ingest-cpu-shed-threshold 0` disables the detector entirely, matching
  pre-ADR-3718 behavior.
