- **CPU-aware ingest admission** (ADR-3718, issue #3720). A background
  detector samples the process's own CPU use and the ingest routers'
  deferred-flush-trigger rate every 100 ms, and moves a shed fraction `p`
  around `--ingest-cpu-shed-threshold` (default 0.95), raising it only after
  a full second of samples with at least one deferred flush trigger. `p` is
  capped at `--ingest-cpu-shed-max` (default 0.5, since a client that retries
  after a doubling backoff parks every worker once `p` is above 0.5). `p`
  steers CPU toward a target 0.05 below the threshold: while
  flush triggers are deferred it rises each sample by 0.03 times the CPU
  error, at least 0.0006, unless CPU is more than 0.02 below the target; with
  none deferred it falls by 0.03 times the error, at most 0.005 per sample,
  only while CPU is more than 0.02 below the target, and otherwise holds,
  rather than releasing whenever CPU dips below a fixed level (issue #3741).
  Nonzero thresholds must be above 0.07. Every OTLP and Remote Write request then draws once against `p` at the head, right
  after the in-flight permit and before the tenant is resolved, so a saturated
  node sheds before doing any tenant work for a request it will refuse. An
  OTAP stream draws once per `BatchArrowRecords` batch, after that batch's
  own in-flight permit; its tenant was resolved when the stream opened, and a
  refused batch ends the stream. Refused requests get 429 with
  `Retry-After: 1` on HTTP and `RESOURCE_EXHAUSTED` on gRPC, counted on the new
  `ravel_ingest_cpu_shed_total{mode}`; the current `p` exports as the gauge
  `ravel_ingest_cpu_shed_fraction{mode}`. `--ingest-cpu-shed-threshold 0`
  disables the detector entirely, matching pre-ADR-3718 behavior.
