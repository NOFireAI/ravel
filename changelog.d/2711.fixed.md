- **OTAP metrics keep their resource identity.** OTAP ingest now reads
  `RESOURCE_ATTRS` and gives each point the `job`, `instance` and allowlisted
  resource labels the OTLP path gives the same input, so series from
  different services no longer merge. Dictionary-encoded attribute columns are
  now decoded instead of skipped. OTAP batches take the same resolved-label
  byte bound, ingest budget charge and per-point summary quantile cap as OTLP,
  and their dropped resource attributes count on
  `ravel_ingest_resource_attrs_dropped_total`. Points stored earlier keep
  their series; new points under a labelled resource start new series. No
  migration is needed.
