- **A log segment at or under the plan bound is read once, without a plan
  read** (ADR-2677 decision 2, issue #2682). The plan bound is the larger of
  `--logs-block-range-threshold` and the projection break-even. A SQL scan of
  logs no longer probes such a segment in its plan phase: one partition opens
  it with a single whole-object GET and prunes blocks from the directory that
  read holds. A selective statement over small objects issues one GET per
  object instead of several, and an undecidable predicate (`has_word`) no
  longer reads such an object twice when it falls outside the plan carry. A
  new `LogsScanExec` metric, `segments_unplanned`, counts these segments, and
  they no longer count in `plan_full_reads`. With a read cache wired, such a
  segment is no longer striped across partitions. Segments above the bound
  keep the planned route.
