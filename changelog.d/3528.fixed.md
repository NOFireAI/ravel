- **A destroyed agent leaves the runtime, and never-committed state reads as
  null.** A coordinator now drops a tombstoned agent from memory: it is not
  offered to a worker poll, a heartbeat on its lease answers `AgentGone`, idle
  unload removes it even with input still queued, and a timer hint of its
  incarnation fires nothing and is deleted, including after the agent is
  created again. A coordinator that did not serve the destroy stops offering
  the agent after one refused dispatch. The `worker_poll_response` fixture and
  the new `state_response_uncommitted` fixture show `state` as `null` before
  an agent's first committed turn, and the TypeScript SDK's
  `TurnAssignment.state` and `StateResponse.state` schemas now say explicitly
  that it may be null.
- **A heartbeat on a destroyed or recreated agent answers `AgentGone`.** A
  heartbeat that reads a tombstoned HEAD also drops the agent from the loaded
  set, so the `agents_loaded` and `turns_active` gauges stop counting it, and
  a heartbeat on a lease of an earlier incarnation answers `AgentGone` rather
  than `OwnershipLost`, the answer the owner's commit gets.
