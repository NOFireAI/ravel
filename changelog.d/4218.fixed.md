- **A restarted server's first logs scan opens its objects from the cache the
  startup warm-up filled, on both the striped and the whole-segment route.**
  The warm-up now runs a logs metadata pass over every logs object in its
  window above the whole-object bound, not only the 4 most recent parts. For
  each object it reads the footer and four directories, no column page, through
  the same fetcher read and under the same cache key the query path looks up
  first, so the first statement issues no footer or directory GET for an
  object the pass reached. Previously the warm-up read only the 4 most recent
  parts, and read each one at or under 512 KiB whole, under a key the ranged
  query path never consults. The pass stays inside the
  warm-up's 10-second deadline, uses at most half of `--cache-max-bytes`
  counting what the cache already holds, reads at most the store GET
  concurrency's number of objects at once, and skips an object whose read
  fails. The `cache warmup: pass complete` line reports
  `metadata_objects_warmed`, `metadata_bytes_warmed` and
  `metadata_budget_reached`.
