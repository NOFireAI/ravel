- **MCP tools that do not run a SQL statement report a memory refusal as
  `budget_exceeded`, not the retryable `unavailable`.** A fetch or catalog
  decode the memory budget refused, and an allocation the allocator refused
  after the budget admitted it, already answered HTTP 422 (ADR-2633 decision
  5), but the query service classed all three as `unavailable` on its PromQL
  and catalog paths, so an MCP client was told to retry a query that needed
  more memory than the server would give it. A tool that runs a SQL statement
  is unchanged: it reports the same refusal as `unsupported`.
