- **`HealthProbeOnMainRouter` condition on a `RavelCluster` still probing the
  main router.** The operator sets it with status `True` and reason
  `DedicatedHealthPortDisabled` whenever the resolved
  `spec.probes.dedicatedHealthPort` is `false`. Since v0.19.0 the CRD has
  defaulted that field to `false` and the API server stores schema defaults on
  every write, so a cluster written since then holds `false` until someone sets
  `true` or removes the field. The message names the main HTTP port and the
  dedicated health listener's port from the operator's own constants and
  points at the upgrade note in `docs/guides/kubernetes.md`. The condition is
  absent, not `False`, once probes resolve to the dedicated listener, whether
  from an explicit `true` or the schema default. This change adds no write to
  `spec.probes`; it only makes the stored state visible.
