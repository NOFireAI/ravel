- **`HealthProbeOnMainRouter` condition on a `RavelCluster` still probing the
  main router.** The operator sets it with status `True` and reason
  `DedicatedHealthPortDisabled` whenever the resolved
  `spec.probes.dedicatedHealthPort` is `false`, which a cluster created under
  the v0.19.0 CRD keeps forever once stored (the schema default flipped to
  `true` one release later, but a CRD schema default only applies on a write
  that omits the field). The message names the main router's port and the
  dedicated health listener's port from the operator's own constants and
  points at the upgrade note in `docs/guides/kubernetes.md`. Absent, not
  `False`, once probes resolve to the dedicated listener, whether from an
  explicit `true` or the schema default. The operator never writes
  `spec.probes`; this only makes the stored state visible.
