- **The L1 memory split target is derived from host memory when unset**
  (issue #2351). `l1_part_memory_target_bytes` now defaults to the memory
  budget divided by 8 and by the number of concurrent merges, clamped to
  [256 MiB, 8 GiB], instead of a fixed 256 MiB that closed wide-schema parts
  at about 2 MB stored. `ravel-server` derives it from its memory budget and
  `--maintain-unit-concurrency` and takes the new
  `--maintain-l1-part-memory-target-bytes` flag; `ravel-cli maintain` derives
  it from the host's total memory and `--bucket-concurrency`. An explicit flag
  still wins, an unknown budget falls back to 256 MiB, and both binaries
  report the value they resolved and where it came from.
