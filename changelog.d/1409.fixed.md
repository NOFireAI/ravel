- **SQL scans of `logs`, `spans`, `alerts` and `audit` now enforce the byte
  and store-request budgets** (issue #1409). Each scan checks the effective
  `max_bytes_scanned` and `max_store_requests`, lowered per request or the
  server's, against the statement total after every store read and before
  the next, and refuses with `TooManyBytesScanned` or
  `RequestBudgetExceeded`, as `samples` already did. Previously those four
  tables checked only the request budget, once at resolve, and never the byte
  budget. A distributed fan-out of those tables now folds worker bytes
  against the effective byte budget instead of an unlimited one.
  `SignalStats::budgets` reports which limits each table's scan checked. A
  request with `row_window` set on the pinned Flight SQL resolve is now
  refused as `RowWindowNotPinned` instead of returning rows outside the
  window.
