- **Write gate trial settings: `--cpu-gate-write-inline-floor-bytes` and
  `--flush-checksum-in-job`.** Both are for the issue #2818 trial and leave
  the server as it was when unset. The first moves the write CPU gate's
  inline floor from its 256 KiB default: `0` sends every flush encode and
  ingest payload decode through the gate, and a value larger than any job
  runs them all inline. The second computes a metrics flush's CRC32C upload
  checksum inside its encode job instead of on the async runtime; the PUT
  sends the same checksum over the same bytes either way. Neither moves the
  checksum the S3 store computes for itself before the upload. The startup
  line logs both. The `ingest_write_gate_overhead` bench takes the same two
  settings as `RAVEL_BENCH_WRITE_INLINE_FLOOR_BYTES` and
  `RAVEL_BENCH_FLUSH_CHECKSUM_IN_JOB`, prints the min, median and max input
  bytes of each configuration's flush encodes, and takes
  `RAVEL_BENCH_TABLE_RUNS`, `RAVEL_BENCH_HTTP_RUN_MS` and
  `RAVEL_BENCH_FLUSH_RUN_MS` for a short table pass. A new advisory bin,
  `ingest_query_latency_trial` (feature `saturation`), reports PromQL and SQL
  query p50/p99 and Remote Write throughput under a fixed 64 KiB snappy load
  at 1 and 16 clients, for four arms: ungated, gated stock, gated with a
  1 MiB floor, and gated with the checksum in the job.
