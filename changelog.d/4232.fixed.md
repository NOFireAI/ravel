- **A `logs` query that projects `attrs` with many declared columns no longer
  searches each row's attributes once per column.** Such a query, `SELECT *`
  among them, is built on the row path. There each declared column and
  `attrs['k']` column looked its key up with a linear search of the row's
  merged attributes, so the cost per row grew with the square of the
  tenant's declared vocabulary. With four or more such columns projected, one
  pass over each row's merged attributes now resolves all of them. The
  values are unchanged: the first entry holding a key still wins.
