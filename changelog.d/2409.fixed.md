- **A metrics erasure rewrite keeps the dedup provenance of every sample it
  keeps** (issue #2409). Rewriting a compacted bucket used to stamp every run
  with the compaction record's own timestamp and a zero writer epoch and
  sequence, and to drop the per-sample provenance column of a run that
  compaction had merged from several writes. A commit that landed in the bucket
  later then resolved against those samples by the wrong key, so a newer
  duplicate it carried could lose to an older rewritten sample. Each
  rewritten run now keeps the provenance its part stored and its per-sample
  column, filtered to the samples that survive. A run with no column that loses
  samples to the erasure gets one holding each survivor's original position,
  so a duplicate decided by that position resolves as before.
