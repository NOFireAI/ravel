- **The PromQL range-query selector cache is bounded by the query's memory budget.** The
  per-query cache that lets a compound range query read each distinct
  selector once (issue #3072) charged its entries to no budget, so a query
  with many distinct selectors over a large pool could hold one copy of that
  pool per selector. Each entry is now reserved against the query memory
  budget and counted toward a per-query cap of two float copies of the
  `max_samples` pool, and both are released when the query ends. A selector
  whose entry does not fit is read at every grid step instead, which returns
  the same result, and the response carries one info annotation naming how
  many selectors fell back and whether the budget or the cap refused them.
  A budget fallback does not move `ravel_memory_budget_refusals_total` or
  `ravel_memory_gate_refusals_total`, since the query still succeeds.
