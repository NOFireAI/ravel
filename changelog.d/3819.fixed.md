- **RLOG compaction reads each input once instead of once per stream it
  carries** (#3819, ADR-3819). The L0 to L1 merge used to fetch an input's
  row group again for every stream in it, so a many-stream logs bucket cost
  about inputs times streams GETs. It now fetches every row group once and
  holds it under a resident ceiling (`merge_cursor_budget_bytes` divided by
  `--maintain-unit-concurrency` in ravel-server), or once per stream-range
  pass when the inputs do not fit, with `input_read_concurrency` fetches in
  flight. On a 12-input, 60-stream test bucket the block GETs fall from 720
  to 12 (resident) or 108 (9 passes). Every L1 segment keeps exactly its
  bytes and key. The merge logs its read mode, and the per-phase request report gains
  the pass count and resident bytes.
