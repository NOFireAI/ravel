- **Ingest routers can enqueue a strict write and await its acknowledgement
  as two steps.** `submit` charges the byte budget and sends the rows to
  their shards, and the returned handle's `acks` waits for the commit
  records; `write` remains the two in sequence, so callers see no change.
  A process-wide bound on pending strict acknowledgements
  (`max_pending_strict_acks`, default 8,192, 0 = unlimited) refuses a strict
  submit past it with a retryable error before anything is charged or sent,
  and the router metrics report the held count and the refusals. The
  server wires the bound and uses the two steps in a later change (#2797);
  until then every router runs unlimited.
