- **`sql_latency_bench --mixed`, a mixed scan-and-interactive workload for the
  read cache's admission (ADR-3072 track P5).** On one generated logs tenant,
  background connections loop full-tenant scans the block statistics cannot
  prune while foreground connections loop a small interactive set over the
  most recent objects, for a fixed duration, once per arm of
  `--cache-bulk-scan-min-bytes` values (`--mixed-arms`, `unset`/`region`/
  `cache`/bytes) per repetition, arms interleaved on a fresh cache each. The
  report (JSON on stdout, table on stderr) carries per arm run and class the
  statements completed, p50/p95/p99, read-cache hits, hit bytes and misses,
  the served share, object-store GETs and wire bytes, all from the
  statements' own `stats.cache` and accounting, plus per-arm medians, the
  pre-registered band rows as HIT/MISS and a per-statement result digest
  across arms. The run exits non-zero when a figure is missing or a class
  with connections completed no statement. `--mixed-foreground 0` is the
  scans-only shape. The generated lane now stamps each object's blake3 hash
  as its commit record's content hash, which the read cache keys entries by.
