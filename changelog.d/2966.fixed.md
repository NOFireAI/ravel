- **Startup no longer misreports jemalloc's background purge thread as
  enabled, or warns as if an operator-facing failure occurred, on a jemalloc
  build with no `background_thread` mallctl at all** (macOS; issue #2966).
  `configure_background_thread` now distinguishes that case (jemalloc's
  `ENOENT`-style "unknown/invalid value" response) from a genuine write
  failure and stamps the allocator state `"unavailable"` instead of
  `"server"`, logging at `info` rather than `warn`.
