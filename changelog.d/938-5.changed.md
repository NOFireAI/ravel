- **One oracle timeout no longer voids a MetricsBench query run** (issue
  #3370). When Prometheus' answer for an entry is lost to a timeout or a
  transport failure, `metricsbench_query` re-sends that oracle query up to
  `--oracle-retries` more times (default 2), one second apart, and names each
  retry on stderr. A 502, 503 or 504 is retried too. Any other received answer
  (another HTTP status, a body over the cap, a body that is not JSON) is not. Prometheus' own row keeps the first
  attempt's outcome, so a retry cannot make it faster. The provenance config
  records `oracle_retries`, `oracle_retries_used` and `oracle_retry_entries`.
  A run whose retries are exhausted is void as before.
