- **The memory gate closes on host available memory, not on the process's
  resident size.** A default-configured server with warm read caches sat
  above the gate's mark (70 % of the memory budget) while the host still had
  9 to 10 GB free, so ordinary work was refused: the ClickBench concurrent
  phase pooled a 0.787 error ratio against 0.071 on v0.23.0, and heavy
  `GROUP BY` statements were refused on a warm server even alone. The
  `ravel-memory-gate` sampler now reads `MemAvailable` from `/proc/meminfo`
  every `--memory-gate-interval-ms` (under a finite cgroup memory limit, the
  smaller of that and the cgroup's headroom, `memory.max` minus
  `memory.current` plus `memory.stat`'s `inactive_file`, re-read on every
  sample) and closes the gate while the reading is below
  `--memory-gate-min-available-bytes`, default `min(max(512 MiB, 2 % of host
  memory), host memory / 8)` (687 MB on a 32 GiB host, 128 MiB on 1 GiB; the
  clamp binds below 4 GiB, so a 1 GiB host or container starts at the
  defaults, and a derived floor under the flag's 64 MiB minimum is
  accepted). Below `--memory-gate-purge-available-bytes` (default the
  smaller of twice the close floor and a quarter of host memory) it forces
  the jemalloc purge, at most once per `--memory-gate-purge-min-interval-ms`
  (default 5000), and re-reads before deciding. A close floor flagged at or
  above a quarter of host memory has no derivable purge floor, and startup
  refuses until `--memory-gate-purge-available-bytes` is passed; a derived
  configuration never refuses. `--memory-gate-high-water-percent` is removed; it landed in #2764
  and no release carries it. `ravel_memory_gate_high_water_bytes` is renamed
  `ravel_memory_gate_available_floor_bytes`; `ravel_memory_gate_available_bytes`
  (the last available reading) and `ravel_memory_gate_purge_floor_bytes` are
  added; `ravel_memory_gate_resident_bytes` stays the last resident reading.
  The gate's refusal message now names the host's available memory and the
  floor. Startup no longer checks the cache caps against a mark; it refuses a
  flagged purge floor not above the close floor and a flagged floor at or
  above host memory, reports `disabled-no-host-memory` when `MemAvailable` or
  `MemTotal` cannot be read, and stamps `available_source` (`meminfo` or
  `meminfo+cgroup`) on the `memory gate resolved` line. For an operator: a
  warm server on a host with free memory admits work, and the gate refuses
  only when the host itself is close to running out.
