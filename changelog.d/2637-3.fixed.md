- **Parquet table listings count the keys the store could not address, and
  `ravel-cli parquet ls` names them** (issue #2637). A resolve or sweep
  listing that skips such a key now records it in a per-tenant count,
  `resolve::unaddressable_listings`, beside the invalid-table count, and
  `TenantListing` carries the skipped keys in a new `unaddressable` field.
  `parquet ls` prints how many keys the store's path encoding cannot
  address and names up to 16 of them, escaped and with the key a request for
  each reaches. `segment inspect` and the other commands that take a file
  path or a store key once again fail with a not-found error for a missing
  absolute path, saying it is not an object store key, instead of the
  store's `UnaddressableKey` refusal.
