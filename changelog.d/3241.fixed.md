- **A logs scan's string values stay charged to the SQL memory pool while a
  filter downstream still holds them.** Previously a filter still collecting
  rows for its next output batch kept one values array per input block alive
  with no charge, so a selective filter over many blocks could hold hundreds
  of megabytes the memory limit never saw. A query that held that memory can
  now fail with a resources-exhausted error under a memory limit instead.
  The charge is still released when the scan ends, before an operator
  downstream has flushed what it holds.
