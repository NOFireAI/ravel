- **SQL spill is on by default when `ravel-server` runs with `--cache-dir`**
  (ADR-0954 amendment, issue #2416). With no spill environment set, an
  eligible query that outgrows its memory pool now spills under
  `<cache-dir>/sql-spill/<instance-id>`, with a per-query ceiling of half the
  free bytes measured at startup on that volume, capped at four times the
  process memory budget and floored at 1 GiB. `RAVEL_SQL_SPILL_DIR` with
  `RAVEL_SQL_SPILL_MAX_BYTES` still wins, and `RAVEL_SQL_SPILL_MAX_BYTES` set
  alone replaces the derived ceiling. The new `--sql-spill off` flag disables
  spill whatever the environment or `--cache-dir` says. Startup logs two more
  `performance default resolved` lines, `sql_spill_dir` and
  `sql_spill_max_bytes`, each with its source. Before serving, a process takes
  an exclusive lock on its own spill directory and removes sibling directories
  whose lock it can take, leaving and logging any whose owner still holds it.
  With spill resolving under `--cache-dir`, startup now refuses to start when
  it cannot create `<cache-dir>/sql-spill`, measure its free space, or lock
  its own directory, and a half-set spill environment names the missing
  variable.
