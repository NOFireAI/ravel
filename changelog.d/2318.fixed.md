- **`tenant parquet-grant add` probes a non-empty object inside the granted
  location** (issue #2318). The object for the `If-Match` precondition probe
  was the first key listed under the location, so a zero-byte folder marker
  such as `data/` or `data/t1/` could be chosen and the probe's ranged read of
  an empty object refused a valid location. Listing `data/t1` without a
  trailing slash could also offer an object under `data/t10/`, outside the
  location. A location naming one object is now checked with a HEAD and
  accepted when the grant admits it and it holds at least one byte. Otherwise
  the location is listed with a trailing slash for up to 8 pages, and a listed
  object has to be admitted by the grant segment by segment and hold at least
  one byte. The listing prefers a `.parquet` key and falls back to any such
  object when it finds none, since the reader accepts a single-object table
  whatever its suffix. The selection is
  `ravel_pqtable::grants::one_object_under`. A location whose only keys are
  folder markers or empty files is refused as holding no object.
