- **A forged Parquet table manifest version can no longer make
  `ravel-cli parquet sweep` delete the real versions beneath it** (ADR-2430,
  issue #2430). A stolen Query credential can create a manifest version above
  a table's newest, and once that aged past the grace the sweep deleted every
  version under it. The manifest gains a MAC (proto field 14, format version
  2): a keyed BLAKE3 over the body under a key derived from the deployment key,
  which object access alone cannot compute. On a keyed bucket the sweep, given
  `--tenant-hash-key-file`, now reads each table's newest version and deletes
  the versions beneath it only when that version carries a valid MAC; a
  version with no MAC or a wrong one holds them all, and the sweep prints each
  held table with the reason. On an unkeyed bucket, where nothing can be
  authenticated, it instead holds them until the newest version is 168 times
  the grace old. This release reads format version 2 and still writes version
  1, so a reader that has not been upgraded never meets a version it refuses;
  because version 1 carries no MAC, a keyed sweep holds every table until the
  follow-up release makes the writer stamp version 2 and the table's next DDL
  statement writes one. The Maintain IAM template gains `s3:GetObject` on
  `t/*/pq/t/*/v/*.pqm` for the sweep's read; update deployed Maintain
  policies before running the sweep on a keyed bucket.
