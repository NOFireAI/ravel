- **Multi-table SQL follow-ups from the ADR-2904 review** (issue #2915). A
  statement over a Parquet table and one signal table now counts both tables on
  the lane request-budget path as the plan does, so its `RequestBudgetExceeded`
  names the table that ran out and the logs column-statistics load reads only
  that scan's own predicates, not a Parquet filter on a column of the same
  name. A pinned plan for a one-signal statement is refused with
  `PinnedSignalsMismatch` when its one lane names a different signal. The
  shadowed-name refusal cuts the table name it echoes to 64 bytes, as it
  already cut the alias.
