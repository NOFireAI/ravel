- **`ravel-cli load` writes objects of about 250,000 rows by default, on
  logs, metrics and spans.** With `--target-bytes` unset the flush target is
  derived as 250,000 rows times the first batch's estimated bytes per row,
  and with `--pipeline-depth` unset the depth is derived as
  ceil(250,000 x `--shards` / `--batch-rows`), lowered to the memory bound
  (`--load-memory-bytes` divided by one batch's estimated bytes, at least 1)
  when that is smaller. Whenever the target is above `1` the loader flushes
  every shard each `--pipeline-depth` submitted batches. `--max-flush-delay`
  now defaults to 60s on every signal. At the previous defaults a 510,000-row
  single-shard load wrote 51 objects; it now writes 3. Every signal's summary
  prints the target and depth with what decided each, the flush trigger mix
  (size, age, depth, manual), the `--target-bytes` no-effect warning when it
  applies, and the same report as one `load report json :` line. To restore
  the previous one-object-per-batch-per-shard layout, pass
  `--target-bytes 1` with an explicit `--batch-rows`.
