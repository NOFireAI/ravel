- **A high-cardinality `GROUP BY` with an exact integer `AVG` no longer holds roughly 1.7x-2.6x the peak memory of the same query with `COUNT(*)`.** (Measured across 8 and 32 partitions, 1.5M groups, five `--release` runs each on the same host before and after this fix.) The exact integer `AVG` accumulator could not convert input rows to partial state, so `skip_partial_aggregation` never applied to it and the emitted partial state sat in the exchange outside the SQL memory reservation. It now converts rows to state: for a `GROUP BY` whose cardinality crosses the configured `skip_partial_aggregation` threshold, the partial `AggregateExec`'s `skipped_aggregation_rows` metric is nonzero and results are unchanged, the same behavior `COUNT` and `SUM` already had (issue #2488, follow-up of #2367).
