- **The catalog fold refuses, rather than rebuilds over, objects a newer build
  wrote.** A previous snapshot part, postings object, per-part column-stats
  object or key-index leaf whose stored version is above the set this build
  reads, or a tenant config record above the read ceiling, now fails the fold
  with `NewerCatalogObject`, naming the object key, kind and version, before
  the HEAD CAS (ADR-4233 decision 4, H1 and H11). Previously the fold rebuilt
  the part from commit records, or folded with default retention and no typed
  columns, and CAS-replaced HEAD, after which the catalog sweep deleted the
  newer objects. A previous object below the read set, or a corrupt one, is
  still rebuilt. A query surface answers the refusal as retryable (503).
