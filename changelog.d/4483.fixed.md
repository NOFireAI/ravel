- **A release that retires a reader no longer refuses its own second start on
  a store it found empty.** On a fresh store (no `sys/compat`, no
  `sys/tenancy`, nothing under `t/`) with a deployment key configured, such a
  release now creates `sys/compat` before it writes anything else: the record
  `ravel-cli compat init` writes on an empty store, plus an empty-census
  certificate and a late-write watermark just past it for each retired
  family. The create is create-only; a process that loses a concurrent create
  starts only if the record it finds passes the retired-reader gate.
  Previously the first start pinned `sys/tenancy` without `sys/compat` and
  every later start was refused. An unkeyed fresh store is unchanged, and no
  current release retires a reader, so none writes `sys/compat` at startup.
