- **Queries wait briefly for memory headroom at admission instead of failing
  their first fetch.** While the process memory budget's reserved bytes are
  at or above `--query-memory-admission-fraction` (default `0.75`, `0`
  disables) of its limit, a PromQL, metadata, SQL or Flight SQL query waits
  at admission, re-checking every 10 ms. It is admitted once the reserved
  bytes drop below the threshold, or after 2 s, or after half its deadline
  if that comes first; in the last two cases it is admitted anyway and its
  own reservations decide, as before. The wait never refuses a query, but
  the time waited comes out of the deadline, so a query that needed nearly
  all of its deadline can now time out. A query the concurrency ceiling would
  refuse is refused at once without waiting. A running query's reservation
  growth never waits, and neither does a distributed scan's internal slice
  fetch. The resolved fraction is logged on the `performance default
  resolved` line, and `ravel_memory_admission_waits_total` and
  `ravel_memory_admission_waits_expired_total` count waits and the waits
  that reached either bound. A SQL or PromQL fetch refused by the
  memory budget now answers "query memory budget exhausted: the process
  could not reserve memory to fetch segment data; retry" instead of
  "upstream storage temporarily unavailable"; status and `errorType` are
  unchanged, and the server's WARN line for a SQL error names the error
  variant.
