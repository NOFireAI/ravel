- **A SQL statement that reads `samples` more than once no longer loses rows to
  one scan's `__name__` filter.** The equality `__name__` predicate on one
  branch of a `UNION ALL`, one side of a self-join, or the outer query of an
  `IN (SELECT ...)` subquery pruned the snapshot every scan in the statement
  reads, so the other scans returned no rows from segments without that
  metric. The prune key is now derived per scan, and the snapshot is pruned
  only when every scan of `samples` requires the same `__name__` value. A
  statement with one scan prunes as before.
