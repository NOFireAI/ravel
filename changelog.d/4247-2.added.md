- **`compat certify` and its late-write pass retire a class-A reader against durable evidence.** `certify` runs a strict census of every live member object of a format family (every commit record's data object and every object under the shard's `l0/` and `l1/` prefixes), holds the certificate behind the activation and per-bucket `G_pre` time gates, and refuses on any member below the target version, any member this build cannot read, and any member whose trailer is absent, corrupt, or disagrees with its record's version stamp. Its census records its start time `S`, target version and activation epoch in a resumable cursor (`sys/maintain/certify/<family>/cursor`), so a run that resumes keeps the earlier `S`; the certificate it writes sets the late-write watermark to `S`, and the daily late-write pass then re-reads records modified since that watermark and marks the certificate contradicted on a lower-version find. The RLOG and RSPAN retention holds now also keep an expired object whose nested POSTINGS or KEY_IDX section version this build cannot read, not only one whose trailer version is out of range (ADR-4233 decision 7, hazard H5).
