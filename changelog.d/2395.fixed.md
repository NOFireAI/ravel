- **The shipped Query IAM template now grants what HTTP Parquet table DDL
  writes** (issue #2395). `deploy/iam/query.json` gains a create-only
  `s3:PutObject` on table manifest version keys only (`QueryManifestCreate`,
  `t/<tenant_hash>/pq/t/*/v/<20 characters>.pqm`, conditioned on
  `s3:if-none-match` `*`, so the role cannot overwrite an existing version),
  and `s3:PutObject` and `s3:DeleteObject` on the bucket probe's
  `sys/pq-probe/*` scratch objects; before this, every `CREATE EXTERNAL TABLE`
  and `DROP TABLE` over `POST /api/v1/sql` was refused on a per-role
  deployment (ADR-0055, HTTP DDL amendment). A new version replaces the table
  for every reader, so a compromised Query credential can define, redefine or
  drop any tenant's table, and can wedge a table with a maximal version
  number. A table definition still reaches only locations the tenant has
  granted, since Query cannot write the grants record; the server's DDL
  authorization does not bind the IAM credential. See `deploy/iam/README.md`,
  "Parquet table DDL", for recovery from a forged version (issue #2430).
