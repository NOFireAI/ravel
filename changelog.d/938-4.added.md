- **MetricsBench runs the PromQL corpus over HTTP against every engine**
  (issue #938). The new `metricsbench_query` binary binds to a
  `metricsbench_ingest` report (anchor, steps, workload digest and seed,
  stream digest, Ravel's commit token), refuses a run whose portable ingest
  rows fail band 6 or their accounting, queries Prometheus as the oracle and
  Ravel, VictoriaMetrics and Mimir against it with one range request per
  range entry, marks native-histogram entries `unsupported_construct` on an
  engine whose ingest row declares the class unsupported, and writes a
  validated version-3 report in which only `ok` rows carry latency.
  `PrometheusClient` gains `with_bearer_token` and `with_extra_params`; a
  bearer token is read from an environment variable and is not written to
  the report.
