- **The logs scan hands its partitions work from one shared queue** (ADR-3072
  decision 2, ADR-0102 decision 1 as amended by #3080). Once the plan
  resolves, its row groups (with a read cache and more than one SQL
  partition) or whole segments (otherwise) are published as units of work,
  and each partition takes the next unit when it finishes its current one,
  instead of being dealt every `n`th block or segment up front, so a
  partition that finishes early takes more of the remaining work. A row group is still read by exactly one partition, the declared
  partition count is unchanged, and a statement returns the same rows. Under
  an ascending `ts` TopK with a read cache the queue follows the earliest
  row groups first. The predicate-free whole-segment fast path keeps its
  round-robin assignment.
