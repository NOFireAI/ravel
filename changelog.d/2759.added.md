- **Per-tenant exact-key index fields for logs.** `ravel-cli typed-attr-column
  set` takes `--key-index KEY` (a declared `str`, `i64` or `bytes` column;
  `bool` is refused), `--no-key-index`, and `--index-trace-id true|false`. The
  logs flush, L0 to L1 compaction and the erasure rewrite then write a KEY_IDX
  section (kind 9) into each RLOG object, listing the blocks that hold each
  distinct value of every named field; the RLOG trailer stays at version 5.
  Turning either setting on writes tenant config record version 4, which a
  release that predates it refuses, so it needs `--readers-rolled-out`
  (ADR-0066 R1, readers first); turning both off needs no opt-in.
  `typed-attr-column show` and `set` print both settings, and `rlog inspect`
  prints the section's version, `bucket_bits` and each field's key type,
  entry count and bucket spread. A retype of an indexed column leaves that
  column unindexed in compacted objects whose inputs mix the two types; a
  merge whose fields exceed the 64-field cap keeps `trace_id` and then the
  names that sort first, which can leave an unchanged column unindexed in
  that output. Neither blocks compaction or erasure, and a query over an
  unindexed column reads the object instead of probing it. No query path
  reads the index yet.
