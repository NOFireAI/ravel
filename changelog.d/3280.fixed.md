- **A partitioned hash join over a grouped declared `Str` key plans again.**
  Previously the cast restoring the key's declared dictionary type sat
  directly under the join and dropped the hash partitioning the join needs,
  so planning failed with `HashJoinExec requires children [0, 1] to be
  co-partitioned`. When both join inputs are grouped on the key and the join
  reads it only in its equality keys, the cast now runs above the join;
  otherwise each grouped input is restored and hash-partitioned again on the
  declared type below the join. `SqlExecutor`
  plans hash joins in `CollectLeft` mode, which this did not affect.
