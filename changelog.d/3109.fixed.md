- **`ravel-cli erase submit` no longer creates the `sys/ipcrypt/policy`
  marker.** With `--ipcrypt-config` on a bucket that has no marker, it used to
  create the marker, so every ravel-server started without that policy then
  refused to start, and submit an erasure whose encrypted matchers matched
  nothing. It now reads the marker and never writes it. With no marker and a
  policy with rules, a request carrying a matcher the policy would encrypt is
  refused before anything is written, with a message saying the bucket's data
  was written without the policy and to submit without `--ipcrypt-config`. A
  request with no encrypted matcher, or an empty policy, is submitted as
  before, and a fingerprint mismatch or an unreadable marker still refuses.
