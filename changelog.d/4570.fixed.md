- **A read with a commit token no longer returns a write's rows twice or
  erased data.** After a compaction, a token read could return an
  acknowledged write's rows twice. On a query node that had cached the write's
  commit record, it could also return data an erasure had removed, once the
  erasure had completed and its request had been released: for metrics after
  any erasure, and for logs and spans after the erasure's rewrite had itself
  been rewritten. Both are fixed. A token read now costs one GET per token
  whose commit record the node had cached, unless the read already holds that
  write's object. A metrics token read now checks the token's bucket as a logs
  or spans read does (one LIST and a GET per rewrite record when the read
  holds a compacted part of that bucket or an erasure is pending), and once a
  tenant has a completed erasure, any token read whose object is not already
  in the read pays that check too.
