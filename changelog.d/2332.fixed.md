- **A gateway or query process that cannot create `sys/gc` under its own
  credential now fails startup with an error naming the start-order fix**
  (issue #2332), rather than the generic "failed to bootstrap or read the
  durable GC config (sys/gc)". Under per-role credentials only the Maintain and
  Admin roles may create `sys/gc`; the error says so and tells the operator to
  start the maintain process first or run `ravel-cli gc-config set` under the
  Admin credential. A maintain or all-in-one process refused the same create is
  told instead which PutObject and `kms:GenerateDataKey` grants the Maintain
  role needs, and any process refused the `sys/gc` read is told it lacks
  GetObject (and `kms:Decrypt` under SSE-KMS), with no start-order advice in
  either case. Every other bootstrap failure keeps its existing message.
