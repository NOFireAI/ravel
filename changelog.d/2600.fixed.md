- **The shard actors' flush age thresholds and deadlines saturate instead of
  wrapping** (issue #2600). The shard actors converted `max_flush_delay`,
  `put_retry_base_delay` and `max_flush_lifetime` to signed nanoseconds with a
  cast: a value between about 292 and 584 years wrapped negative, and a longer
  one kept only its low 64 bits, which can read as any value, negative or not.
  Each now saturates at the largest signed nanosecond count instead. A
  `max_flush_delay` that wrapped negative made a waiting buffer due on every
  tick; it now gives an age threshold no buffer reaches. A
  `put_retry_base_delay` that wrapped negative widened the adaptive flush
  delay's ceiling by its own magnitude; it now leaves no retry headroom under
  the strict visibility budget, so that ceiling collapses to `max_flush_delay`.
  A `max_flush_lifetime` that wrapped negative put every flush deadline in the
  past, so every flush was abandoned; it is now an effectively unbounded
  lifetime. The server refuses such a flush delay at startup and exposes
  neither of the other two as a flag, so only code that builds an
  `IngestConfig` directly could reach these values. The WARN for a flush
  written in place in an hour another shard generation owns now logs once per
  tenant, per cause and per ingest hour, rather than on every such flush, and
  a flush of that tenant that opens in the scan set or hands all its rows over
  lets the next one warn again; the in-place counter still moves on every
  write. A shard that writes such a flush in place with nothing handed back
  logs its next hand-back again.
