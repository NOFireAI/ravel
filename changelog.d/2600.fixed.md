- **The shard actors' flush age thresholds and deadlines saturate instead of
  wrapping** (issue #2600). Code that builds an `IngestConfig` directly with a
  `max_flush_delay`, `put_retry_base_delay` or `max_flush_lifetime` past about
  292 years now gets an age threshold no buffer reaches and an effectively
  unbounded flush lifetime, where each wrapped negative and flushed a waiting
  buffer on every tick or abandoned every flush; the server refuses such a
  flush delay at startup and exposes neither of the other two as a flag, so
  only such code could reach the wrap. The WARN for a flush written in place in
  an hour another shard generation owns now logs once per tenant until a flush
  of that tenant opens in the scan set or hands all its rows over, rather than
  on every flush, and a shard that writes such a flush in place logs its next
  hand-back again.
