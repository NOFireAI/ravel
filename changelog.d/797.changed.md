- **TopK late materialization's row fetch reads only the winners' blocks.**
  Phase 2 of a logs `ORDER BY ... LIMIT k` statement now opens each winning
  segment once for all of its winning blocks instead of once per block.
  Above the block-range threshold, for a version-4 object whose block prune
  is the ts window and numeric ranges alone, the ranged read fetches only
  the winning blocks' projected pages, and the whole-object coverage
  decision weighs those pages' bytes. Other queries and version-3 objects
  keep the ordinary fetch, once per segment. Results are unchanged.
