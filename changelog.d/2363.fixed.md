- **`ravel-cli` Maintain-credential data writes can go out under the tenant's
  KMS key** (issue #2363). `maintain compact-bucket`, `compact-tenant`,
  `migrate` and `catalog fold` take ravel-server's `--tenant-kms-config` flag
  and, when it is given, route their data writes through the tenant's key the
  way the servers do; without the flag they still write under the bucket's
  default encryption. A command creates the tenant's key-epoch record when it
  is absent, but never records a key change: when the record's current key
  differs from the file's it refuses before any write, since only ravel-server
  startup records a rotation. The key-epoch record itself, `maintain sweep`'s
  unnamed-since markers, `load`'s writes and the Admin control records stay
  under the bucket default, and the `commit reconstruct` access-denied error
  now says so for the Admin records.
