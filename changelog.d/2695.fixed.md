- **The server's PromQL, LogQL, analytics and SQL `samples` reads now run
  their decodes and large evaluations on the read CPU gate** (issue #2695,
  ADR-1702). A started server built its query engine without the gate, so
  every RSEG and RLOG catalog decode behind `/api/v1/query`,
  `/api/v1/query_range`, LogQL, analytics and alert evaluation ran on a tokio
  worker, as did every PromQL evaluation however many samples it read. The
  engine now carries the server's read gate: those decodes count under
  `ravel_cpu_gate_jobs_total{gate="read"}` (or `inline_total` below the
  256 KiB floor) at `segment_section`, `segment_sparse_catalog`,
  `log_postings`, `log_block` and `log_section`, and an evaluation of at
  least 100,000 samples runs on the gate as a `promql_eval` job. The SQL
  `samples` table's RSEG catalog decodes, the distributed fragment worker's
  slice fetches and the startup cache warmup now run on the same gate. Two
  open-time decodes stay inline on a tokio worker, as an ADR-1702 amendment
  records: an RLOG object's plan-phase directory sections, and an RSPAN
  object's footer, skip index and bloom.
