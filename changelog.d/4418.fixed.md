- **A logs or spans query with a commit token counts each record once after
  the token's write is compacted (#4418).** Until the sweep deleted the
  compacted input's commit record, the token step added that input beside
  the part that already held its rows, and logs and spans have no
  query-time dedup, so every record of the write was returned twice. The
  step now leaves out an input whose rows the snapshot already serves from
  a compaction or rewrite output, and an input a live erasure rewrite
  replaced, deciding from the records' input sets. A token whose write is
  not compacted is still served from its own object, and metrics are
  unchanged. The check costs one LIST of the token's bucket, plus one GET
  per compaction record not in the cache and per rewrite record, and runs
  only when the snapshot holds a level-1 part of that bucket or an
  erasure is pending.
