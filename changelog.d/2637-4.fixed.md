- **An S3 listing no longer fails on a key that does not URL-decode or on a
  sparse page** (issue #2637). A key or common prefix holding a `%` not
  followed by two hex digits used to fail the whole listing; it is now
  reported in `unaddressable` with its still-encoded text, counted in
  `ravel_store_list_unaddressable_total` and warned about, and the rest of
  the listing is returned. The response ceiling of a `list` or `list_after`
  call now counts keyless responses in a row, 16 at most, and a response
  carrying a key starts the count again, so a page over a mostly deleted
  prefix no longer fails with `ListPageCeiling` while it is still receiving
  keys. One call sends at most `16 × page_size` requests. For a missing
  absolute path, `segment inspect` and the other commands that take a file
  path or a store key now say the value is not a readable file and that a
  request for it as a key would reach the named key instead.
