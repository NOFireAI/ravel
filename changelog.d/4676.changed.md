- **A dominant group key is combined before the hash exchange.** Between a
  partial aggregate and its hash exchange, SQL plans now run a combiner that
  merges the rows of a frequent group key in each input partition, so a key
  holding most of a scan's rows reaches the final partition that owns it as a
  few state rows instead of one row each. It holds at most `2P - 1` groups per
  input partition, `P` being the exchange's partitions, and answers are
  unchanged. `EXPLAIN ANALYZE` shows it as `DominantKeyCombinerExec` with
  `merged_rows`, `forwarded_rows`, `emitted_states`, `held_groups_peak` and
  `decrement_passes`. `SqlConfig::dominant_key_combiner` (default on) turns it
  off; there is no server flag.
