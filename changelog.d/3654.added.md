- **`ravel-otlp` vendors the OTLP logs protos with six hot `string` fields
  retyped as `bytes`** (issue #3654, ADR-3492 D3b). `crates/ravel-otlp/proto/`
  checks in the upstream `opentelemetry-proto` v1.10.0 logs protos verbatim
  alongside a copy with `KeyValue.key`, `AnyValue.string_value`,
  `LogRecord.severity_text`, `LogRecord.event_name`,
  `InstrumentationScope.name` and `InstrumentationScope.version` retyped to
  `bytes`; every other field, package name and field number is unchanged. The
  new `ravel_otlp::vendored_logs` module compiles the retyped protos with
  `protox` and `prost-build` (message types only, no service code) and
  decodes those six fields as a refcounted `bytes::Bytes` slice of the
  request body instead of copying them into a `String`; `validate_utf8`
  checks each one and names the failing field, so the accepted request set
  matches upstream's `String`-typed decode exactly. Nothing reads from this
  module yet: it exists to be measured, and its own bench
  (`vendored_logs_decode`) reports whether the retype is worth wiring into
  the ingest path in a follow-up step.
