- **The allocator background-thread gauge and failed-start warnings match
  what happened** (issue #3140). After a failed start of jemalloc's
  background purge thread, `ravel_process_allocator_background_thread`
  stayed at 0 even if a later start in the same process succeeded; the flag
  behind it now follows the latest start. The server starts the thread once,
  so a running server is unaffected. A start that failed before jemalloc
  reached the setting (EAGAIN, a memory allocation failure) no longer writes
  the thread back off or warns that decay purging is off until restart: it
  logs one warning saying the setting and decay purging are as they were,
  and still stamps `source="start-failed"`. When the server cannot tell
  whether a failed start set jemalloc's enabled flag, the follow-up warning
  now says decay purging is off only if it did.
