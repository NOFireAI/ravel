- **Maintain memo snapshots are authenticated.** A principal holding the
  maintain role's S3 write could previously put a snapshot under
  `sys/maintain/memo/` that seeded terminal verdicts into every maintain
  process, so the owners of those buckets skipped them until the verdicts went
  stale. Each snapshot now carries a MAC
  under the `--maintain-key-file` keys over the writer's process id, which a
  reader takes from the object key, so a snapshot without a valid MAC, or one
  copied under another process's key, seeds nothing and is never decoded.
  Rejected snapshots are logged with a count per reason. During a rolling
  upgrade, processes on this release and on an earlier release cannot read
  each other's snapshots, so each maintenance unit starts cold once and
  rescans its buckets.
