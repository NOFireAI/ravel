- **`ravel-cli compat` refusals exit 5, not 2, and `compat activate` takes
  the writer-role attestation as its own flag.** A refused `compat`
  command (an unkeyed store, a missing attestation, an unwritable version,
  the certify time gate, a held member) now exits 5 instead of 2, so a
  script can tell it from clap's usage error, which still exits 2; 0, 1, 3
  and 4 keep their meanings. A script that tests for 2 on a refusal must
  test for 5. `compat activate` now also requires
  `--writer-roles-can-read-compat`, which alone attests that every writer
  role can read `sys/compat`; `--pre-baseline-processes-terminated` no
  longer implies it. Both attestations are recorded in `activated_by`, and
  the refusal and `--help` name the residual: a writer role not granted
  read on `sys/compat` keeps writing the baseline version to unprovisioned
  paths and to buckets it first touches after the activation.
  `compat status` and `compat verify` now report `finalization_pending` as
  the maintain process and the retired-reader gate compute it: true while
  an uncontradicted certificate's watermark is at or below
  `certified_unix_ns`, so at equality it now reads `true`, and a
  contradicted certificate now reads `false`. The `ConcurrentCertify`
  refusal now says the run lost a conditional write on the certify cursor
  and that a rerun resumes from whatever cursor is there, instead of
  "another certify run owns the cursor". `docs/reference/ravel-cli-flags.md` now lists the
  `--version` flag of `compat activate` and `compat certify`.
