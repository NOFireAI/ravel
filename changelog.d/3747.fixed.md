- **A PromQL read no longer holds every object's samples outside the memory
  budget** (issue #3747). The local sample prefetch folds each object's scalar
  and histogram runs into one per-series accumulator as the object's fetch
  completes, with the result `merge_soa_runs` gives in any completion order
  (`scalar_fold_equals_the_merge_in_any_completion_order`), and reserves what
  the fold holds against the engine memory budget. A series carried by many
  objects is held and charged once
  (`a_sample_read_holds_one_copy_of_each_series_across_objects`), and a read
  whose merged samples do not fit is refused with `FetchMemoryExhausted`
  against the budget's limit instead of reaching the host-memory floor
  (`a_sample_read_that_outgrows_the_budget_is_refused_against_it`).

  Upgrade note: the fold charges about 24 bytes per held scalar sample, and
  substantially more per native-histogram sample, whose spans and buckets are
  charged too, plus each series' labels. A large PromQL read can therefore now be refused by the
  memory budget at fetch time, where before it grew outside the budget
  until it answered or the host floor refused it. The two refusals read
  differently:
  - a budget refusal: `memory exhausted: requested N bytes, X of Y byte
    limit already reserved`, counted in `ravel_memory_budget_refusals_total`;
  - a host-floor refusal: `memory exhausted: host available memory N bytes
    is below the M byte floor (requested R)`, counted in
    `ravel_memory_gate_refusals_total`.

  To admit such a read, raise the budget with `--memory-budget-bytes` (on
  Kubernetes, `query.memoryBudgetBytes`), or narrow the statement's time
  range or series. `max_series` is now checked as series arrive, so that
  refusal can come before the last object is fetched.
