- **A memory gate samples host memory and jemalloc and purges under
  pressure.** Each `all`, `query` and `maintain` process runs a
  `ravel-memory-gate` thread that reads host available memory and jemalloc
  `stats.resident` every `--memory-gate-interval-ms` (default 100). Below a
  purge floor it forces a purge of every arena's dirty and muzzy pages,
  restores their decay settings, and re-reads; while available memory is
  below the close floor the gate is closed and refuses memory reservations
  until a reading recovers (the floors, their flags and their defaults are
  under the #2806 entry in this release). The gate is off in `gateway` mode,
  with a fallback-sized budget, under `--disable-memory-gate`, without
  jemalloc, and when host memory cannot be read; the `memory gate resolved`
  startup line says which. `--memory-gate-wait-ms` is resolved and stamped
  but not yet read. New `/metrics` families: `ravel_memory_gate_resident_bytes`,
  `ravel_memory_gate_available_bytes`,
  `ravel_memory_gate_available_floor_bytes`,
  `ravel_memory_gate_purge_floor_bytes`, `ravel_memory_gate_purges_total`,
  `ravel_memory_gate_samples_total`,
  `ravel_memory_gate_epoch_refresh_seconds_total`,
  `ravel_memory_gate_purge_seconds`, and `ravel_memory_gate_refusals_total`
  and `ravel_memory_budget_refusals_total` by `site`.
