- **A Parquet decoder error while scanning a corrupt file now answers like a decoder panic does.** Some corrupt page headers and page bodies end the scan in a decoder error, such as `EOF: eof decoding byte array` or `Required field type_ is missing`, rather than a panic. A SQL query that hit one used to fail as an execution error (HTTP 422) carrying that bare message, which named neither the file nor the table. It now fails as the integrity-validation error, `stored data failed integrity validation` (HTTP 500), the same answer a decoder panic on a corrupt file already gave. The file and the table are named in the server-side error; the client sees only the integrity-validation message.
