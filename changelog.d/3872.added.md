- **A many-input RLOG bucket merges in two levels instead of being refused**
  (#3872, ADR-3853 T3a). With the new `scratch_dir` maintain setting, a
  bucket whose single-level plan is not resident merges each contiguous group
  of `G` canonical inputs into a run in that local directory, `G` the largest
  group whose resident blocks plus the run memory target
  (`rlog_run_memory_target_bytes`, 256 MiB by default) fit the ceiling, then
  merges the runs into the published L1 objects. Every published object keeps
  the bytes and key the single-level merge writes. Before its first block GET the merge
  refuses a group size under 2 (`MergeTwoLevelUnsupported`) and a scratch
  volume with less than 1.3 times the inputs' object sizes free
  (`ScratchHeadroom`); after level 1 it refuses a level 2 whose runs do not
  fit the ceiling (`MergeTwoLevelUnsupported`). Each refusal names the check
  that failed and ends with the merge outcome `refused`. The scratch directory is emptied
  however the merge ends. The request ledger gains `level1_groups`,
  `level1_passes`, `level2_passes`, `level1_block_decodes`,
  `level2_block_decodes`, `scratch_write_bytes` and `scratch_read_bytes`.
  With no `scratch_dir` (the default, and every caller today), the merge and
  the #3870 refusal are unchanged.
