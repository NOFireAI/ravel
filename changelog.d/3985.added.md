- **An unordered `GROUP BY ... LIMIT n` holds only `n` groups in its final aggregate.** A statement such as ClickBench's `GROUP BY "UserID", "SearchPhrase" LIMIT 10` charged 2.5 to 2.8 GB to build every group and was sometimes refused at an 8 GB host's process limit; a new `FirstGroupsExec` under the final aggregate now passes only the rows of the first `n + s` groups (for `OFFSET s LIMIT n`) each final partition sees, so the answer stays exact and the memory follows `n`. Statements with an `ORDER BY`, a `HAVING` filter, grouping sets or no aggregate expression are unchanged, as is any bound above `SqlConfig::bounded_groups_max_limit` (default 1024; 0 turns the rule off, and ravel-server has no flag for it) (ADR-3985).
