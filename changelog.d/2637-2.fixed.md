- **S3 listings return raw keys, so a key holding a control character no
  longer fails the whole listing** (issue #2637). `S3Store::list`,
  `list_after` and `list_delimited` now send their own signed ListObjectsV2
  request instead of listing through `object_store`: the prefix and the
  resume key go on the wire as written, keys come back URL-decoded, and an
  unaddressable key or common prefix is reported in `unaddressable` or
  `unaddressable_prefixes` with the rest of its page intact. A page that
  ends on a key holding `#` or `*` now resumes from that key itself, so the
  next page neither skips keys nor repeats them. A listing that repeats a
  continuation token, runs past its response ceiling or reports truncation
  with no token fails with a typed error instead of looping, and a 403,
  3xx or other 4xx is not retried. A 3xx is not followed either, with or
  without a `Location` header: it fails as a permanent error naming the
  configured region and endpoint. `store qualify` gains the
  `listed_keys_round_trip_plus_and_space` probe, which checks that keys
  holding `+` and spaces list back verbatim, and the conformance suite
  version rises from 2 to 3 with it. ravel-server refuses startup on a
  `sys/qualification` record written at version 2 as stale: after
  upgrading, re-run `ravel-cli store qualify` with the new build against
  each bucket, which replaces the version 2 record in place.
