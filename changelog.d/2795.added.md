- **`--sql-scan-decode-inline` puts the SQL `logs` and `spans` scan-block
  decode back on the polling worker** (env `RAVEL_SQL_SCAN_DECODE_INLINE`,
  default off). When set, those two scans decode their blocks inline instead
  of on the read CPU gate, as before ADR-1702 follow-up task 8, and every gate
  site their fetchers use (`log_block`, `log_postings`, `log_section` and
  `span_block`) counts nothing for SQL statements. The catalog,
  PromQL, maintenance and SQL `samples` gate sites keep the gate. Startup logs
  which mode the SQL scans run in. The flag exists to A/B the gate's cost
  against its liveness benefit (issue #2795); setting it gives up the
  isolation the gate gives scans.
