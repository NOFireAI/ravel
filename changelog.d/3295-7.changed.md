- **A logs `LIKE '%lit%'` pushed into the scan no longer fetches the BLOOM and
  POSTINGS sections** (issue #3295). The ranged object fetch placed both
  sections for any content predicate, but a `Contains` arm is checked row by
  row and drops no block, so the reader never decoded them: on a
  ClickBench-shaped fixture the pushed statement fetched 28 requests and
  748,622 bytes against 20 and 651,322 with the LIKE above the scan. Both now
  issue the same requests. Content predicates that do drop blocks (a token
  match, a short equality, an attribute equality, a time range, a stream
  filter) still fetch the sections.
