- **A `GROUP BY ... ORDER BY <group key> LIMIT n` holds only its best keys in its final aggregate.** A statement such as ClickBench row 43's per-minute page (`ORDER BY M LIMIT 10 OFFSET 1000`) built every group before the sort picked a page; a new `TopKeysAggregateExec` replaces the final aggregate and cuts each partition back to its best `n + s` keys whenever it holds twice that many, so the charged peak on a 1,000,000-key fixture falls from 60 to 71 MB to 4.1 to 8.9 MB and every returned group keeps its exact aggregates. Float keys, aggregates with float state, `FILTER` or `ORDER BY` inside an aggregate, a `HAVING` filter, an order by an aggregate, and a bound above `SqlConfig::bounded_top_keys_max_limit` (default 1024; 0 turns the rule off, and ravel-server has no flag for it) keep the existing plan (ADR-4002).
