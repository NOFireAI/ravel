- **A failed start of jemalloc's background purge thread is reported as not
  running, and the setting is turned back off** (issue #3096). When the host
  refused to create the thread, the server logged a warning and then stamped
  `allocator_background_thread=true source="server"`, and
  `ravel_process_allocator_background_thread` read `1`, because jemalloc sets
  its enabled flag before it creates the thread and leaves it set when
  creation fails. With that flag set and no thread running, no timed purge
  ran at all. The startup stamp now reads
  `allocator_background_thread=false source="start-failed"`, the gauge reads
  `0` for the life of the process, and the server writes
  `background_thread=false` so freed pages return to the operating system
  during later allocator calls, as with `background_thread:false`. If that
  write fails too, a second warning says that no timed purge runs until
  restart and freed pages return only through forced purges.
