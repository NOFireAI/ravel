- **Spans `trace_id` lookups read the trace's block run by range.** A lookup
  that pins a `trace_id` reads the object's 64 KiB tail (the footer and, when
  it reaches them, SKIP_IDX and BLOOM), then one ranged GET per contiguous
  run of candidate blocks, never the whole object through `GetRange::Full`;
  the rows, `stats.pruning` and the per-block page bytes are those of the
  whole-object path, and the scan phase reports the ranged requests and
  wire bytes as transferred. The process read cache now fronts span reads
  as it fronts logs and metrics reads, keyed by tenant, object content hash,
  offset and length, so a repeated lookup issues no GET.
  `RspanRangeReader::block_run_span` reads one explicit contiguous block run
  and refuses any other set.
