- **The alert evaluator refuses its tick on an unreadable-version history
  object instead of rebuilding state without it.** When a tenant's alert
  history holds an object whose RLOG format version this build cannot read,
  and whose bytes match its commit record's content hash, the evaluator used
  to skip the object and fold the rest, which re-fired or dropped the
  transitions it held. The tick now refuses with a typed error (ADR-4233
  decision 4, hazard H3): it keeps the previous durable state, writes no
  transition and no state memo, re-queues no notification from the incomplete
  fold, and reports `outcome="history_unavailable"`. The counter
  `ravel_alert_history_records_skipped_total{reason="unsupported_version"}`
  keeps its name but now counts refused ticks; because a refused tick writes
  no memo, it rises every tick until the object is retired or every reader is
  upgraded. An object whose bytes do not match the content hash is corruption
  and fails the tick as before.
