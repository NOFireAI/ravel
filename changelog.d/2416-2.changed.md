- **An `ORDER BY` over a spill-eligible aggregation can now spill** (ADR-0954
  amendment, issue #2416). Previously any `Sort` kept a query from spilling.
  Whenever a statement's plan has a `Sort` directly over such an aggregation
  (or over a projection directly over it), its sort key gets the
  aggregation's `GROUP BY` columns appended as trailing tiebreak terms,
  ascending with nulls last, whatever the spill setting. The order is then
  total, and the statement returns the same rows in the same order with
  spill forced, with spill off, and in memory. A group column the projection
  renames is matched under its new name, one it drops is carried through to
  the sort and removed again, and a select-list alias that only shares a
  group column's name is not taken for it. A `Sort` over grouping sets, over
  a `HAVING` filter, or over nested projections is left as written and still
  keeps the query from spilling.
