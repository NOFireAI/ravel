- **SQL logs scans free each block's decoded columns on the thread that
  decoded them.** With the read CPU gate on, the columnar logs scan kept each
  block's decoded columns until the next block's decode, which could run on
  another thread, so every block paid a cross-thread free of thousands of
  small allocations; issue #2795 traces a +14% ClickBench logs aggregate
  regression to it. The block's job now frees them, and releases their
  memory charge, before it returns.
