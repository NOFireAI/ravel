- **SQL logs scans free each block's decoded columns on the thread that
  decoded them.** With the read CPU gate on, the columnar logs scan kept each
  block's decoded columns until the next block's decode, which could run on
  another thread. A block with plain-encoded string or fixed-width columns
  holds one small allocation per present cell of each such column, so it paid
  a cross-thread free of up to thousands of them. Issue #2795 attributes a
  +14% ClickBench logs aggregate regression to that cross-thread free, from a
  microbench of the mechanism; the effect of this change on ClickBench has not
  been measured yet. The block's job now frees them, and releases their memory
  charge, before it returns.
