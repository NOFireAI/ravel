- **SQL logs scans no longer lose time freeing each block on another thread.**
  With the read CPU gate on, the columnar logs scan kept each block's decoded
  columns until the next block's decode, which could run on another thread,
  so every block paid a cross-thread free of thousands of small allocations
  (a +14% regression on ClickBench logs aggregates). The block job now frees
  them, and releases their memory charge, before it returns.
