- **The SQL logs and spans scans no longer pay one read CPU gate job per
  block** (issue #2795). Moving block decodes onto the read gate (#2715)
  submitted one job per block, which cost about 15% of hot time on
  ClickBench's CPU-heavy logs aggregates on the reference box. One gate job
  now decodes a run of consecutive blocks of the same part, up to 8 blocks
  and no further block once the run holds 16 MiB, on the logs columnar and
  row paths and the spans scans; the decodes stay on the gate. A run's
  decoded logs blocks are charged to the query's memory pool as the job
  produces them. A pushed `LIMIT` or a confirmed TopK threshold keeps one
  block per job, and a stream dropped mid-run stops its job after the block
  it is on. `ravel_cpu_gate_jobs_total` and `ravel_cpu_gate_inline_total`
  now count one per run, not per block, for these scans' `log_block` jobs
  and for every `span_block` job.
