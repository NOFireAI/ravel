- **The Kubernetes operator keeps the fragment NetworkPolicy until the query
  rollout completes, and a distributed-query Secret rotation rolls the query
  pods** (issue #2403). Disabling distributed query used to delete the
  `<cluster>-query-fragment` NetworkPolicy as soon as the new query Deployment
  was applied, leaving port 4319 on the old pods reachable from the namespace
  for the rest of the rolling update. The delete now waits until the query
  Deployment's `status.observedGeneration` equals its `metadata.generation`,
  `status.updatedReplicas` equals `status.replicas`, and
  `status.unavailableReplicas` is zero or absent. A change that narrows the
  policy while distributed query stays on, such as turning
  `spec.probes.dedicatedHealthPort` off, keeps the wider policy until the same
  condition holds. The four distributed-query Secrets' `resourceVersion`s now
  feed the query pod template's secrets checksum, so rotating a fragment
  certificate, CA or key file, or the SQL ticket key, rolls the query pods
  without a manual `kubectl rollout restart`; the first reconcile after the
  upgrade rolls the query pods once on a cluster with distributed query
  enabled, and a referenced Secret that does not exist now fails the
  reconcile with `SecretNotFound`.
