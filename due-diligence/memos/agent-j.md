# Agent J memo: verification and test quality

## Verdict

Correctness verification in this repository is unusually strong and unusually honest, and performance and operational-resilience verification is close to absent; the two halves deserve opposite grades. The failure-injection substrate (FaultStore with applied-but-error ambiguity, asserted fault counters in 160 call sites across 80 files), the crash matrices, the GC horizon tests, the PromQL differential gate against a checksum-pinned real Prometheus 3.13.1, and the anti-vacuity discipline (tests that prove their own fault fired, spec-model coverage explicitly labeled as not-production evidence) are the best I have reviewed at this scale. Against that: the only performance numbers committed anywhere are byte counts, the one headline number in CHANGELOG.md quotes an arm its own ADR amendment calls "a worst-case control, not the representative cost", the sole real-S3 benchmark lane runs weekly, skips green without credentials, measures a 10-second workload at a non-production flush cadence, and discards its output after 90 days; the chaos/DR process-kill lane that ADR-0077 marks Accepted contains at least four independent defects that make it unable to ever pass (verified firsthand), has never been run, and no automated test anywhere kills a maintain worker and asserts takeover; there is zero soak evidence of any kind; and the CI required-check topology has holes (a required k8s check that structurally cannot run in the merge queue, an area-gate that lets non-crate diffs skip five lanes, four Docker e2e tests that are ignored everywhere, six cargo-fuzz targets never built by any automation). The suite proves the system is correct under the failures its authors enumerated; it does not yet prove the system performs, endures, or survives real process death, and several of the documents that claim otherwise are ahead of the evidence.

## Evidence

### FaultStore and MemoryStore quality: VERIFIED, including ambiguous outcomes

- Ambiguous applied-but-error outcomes exist and are first-class: `ScriptedFault::DuplicateDelivery` applies the wrapped operation for real and then returns `Transient`, modeling an ack lost after apply, for put/get/head/list/delete (crates/ravel-object-store/src/fault.rs:117-119, 837-840, 972-975). `PartialWriteThenError` and `FailedConditionalWrite` never touch the backend so the object stays invisible (fault.rs:830-836). `CorruptRange` returns real bytes bit-flipped, `EtagChange` returns real bytes under a changed etag to drive the fetcher's snapshot-pinning guard (fault.rs:859-869). `NotFoundBlip` models eventual-consistency read blips.
- Every injected fault is counted per (Op, FaultKind) (fault.rs:646-648), sequences expose `sequence_progress` (fault.rs:639-644), and a hold/release gate primitive drives completion ordering of concurrently in-flight calls including per-part multipart completion (fault.rs:760-807).
- Counters are actually asserted by consumers, not just available: 160 `fault_count`/`sequence_progress`/`counters_snapshot` assertions across the tree (grep count), with explicit prove-the-fault-fired comments, for example crates/ravel-failure-tests/tests/crash_matrix.rs:76-84 ("Without this, an ingest error raised before the PUT ... would satisfy every other assertion below while never exercising the crash path this row names").
- MemoryStore is a real oracle: strong consistency, conditional writes, monotonic versions, injectable clock, and `with_page_size` to force pagination (crates/ravel-object-store/src/memory.rs:1-60). The conformance suite is correctly framed as falsification, not proof (crates/ravel-object-store/src/conformance.rs:13-17), and panel-run evidence shows the contract suite 116/116 green including a live MinIO run, plus `ravel-cli store qualify` passing 4 blocking probes against live MinIO.
- What FaultStore structurally cannot represent: an incomplete or stale LIST (a listing that omits a key that exists), network-level partitions or latency, and multi-process contention on one store from genuinely parallel OS processes. The transport layer does get separate real-socket coverage: crates/ravel-object-store/tests/s3_http_faults.rs stands up a fake S3 on loopback and scripts 503/429/SlowDown/mid-response connection drops, asserting attempt counts server-side.

### The seeded simulation (ravel-sim, ADR-0068): invariants VERIFIED, interleaving search NOT IMPLEMENTED

What it drives: one seeded cycle per master seed, ingest through the real `IngestRouter`, fold through the real `Catalog`, compaction and sweep through ravel-maintain's real `compact_bucket`/`sweep_shard`, query through the real `QueryEngine`, all over MemoryStore on a single-threaded paused-clock runtime (crates/ravel-sim/src/driver.rs:1-22, 766-781). Per cycle it checks: read-your-write and strict-ack-implies-durable against an independent oracle (expected label set, original timestamp, and value compared by bit pattern, computed from the generated workload, driver.rs:1474-1509); bit-exact query equivalence before/after compaction and after physical sweep; record-count conservation; no sweep leaks past the horizon via a second verification sweep that must find nothing (driver.rs:1189-1302). Failures embed the seed and a one-command replay line. The acceptance test proves non-vacuity: buckets_compacted > 0, every scheduled fault's counter positive (crates/ravel-sim/tests/compaction_equivalence_under_faults.rs:56-83). The silent-loss guard has its own injected-mismatch flip test (driver.rs:1596-1642). PR CI runs seeds 1..=5, nightly runs 200 (crates/ravel-sim/tests/seed_batch.rs:11; .github/workflows/sim-nightly.yml:49-51); panel-run evidence: a 100-seed batch green at this commit.

What it structurally cannot find:

- The fault schedule is deliberately confined to faults the exercised paths recover from: retryable PUT faults on `/l0/` and `/c/` during ingest (Nth 1..=2, flavor transient-vs-throttled is the only seed-varying choice), one PartialWriteThenError on the L1 write plus one NotFoundBlip on the L0 read during compaction, one retryable List fault during sweep (crates/ravel-sim/src/fault_plan.rs:9-36, 171-293). The module docs state why: any fault outside this set "would fail a phase the harness has no retry hook for." So seeds vary the workload, not the failure space; the sim can never discover an unhandled fault interaction on fold writes, query reads, or non-retryable paths.
- ADR-0068 promises interleaving search: decision 4 says gates make "operation interleavings (not just failures) searchable" and the consequences say the harness "searches interleavings via gates and schedules" (docs/adrs/0068-deterministic-simulation-harness.md). The shipped generator arms at most one gate (`max_gates: 1`, fault_plan.rs:91-98), on the same two ingest PUT targets, and the default releaser frees each held call the instant it is held, which the code itself says "proves nothing about the call having actually blocked" (driver.rs:208-215). Phase order is fixed. The races the ADR names as motivation (racing compactors, stale HEADs, sweep racing a pinned query, fold racing a late commit) are covered only by the hand-written matrices the ADR said were insufficient (crates/ravel-maintain/tests/crash_matrix.rs:174 row10 racing compactors; sweep_crash_matrix.rs:311 row9; folder_crash_matrix.rs:297 HEAD CAS race). The gate machinery itself is proven non-vacuous per gate (CycleError::GateNeverHit per-gate counters, driver.rs:1325-1339; crates/ravel-sim/tests/hold_release_gates_drive_cycle.rs:1-20), so the seam exists; the search does not.
- The workload generator is non-adversarial: 2 tenants x 12 series x 8 samples default, values in [-100,100] random walk, regular 1 s grid, no NaN, no -0.0, no infinities, no duplicate or out-of-order timestamps, no late data, no counter resets; queries are bare selectors and `histogram_count()` only (crates/ravel-sim/src/workload.rs:61-74, 190-253, 255-295).
- Structural non-representables: real S3 semantics (MemoryStore only; the contract suite and bench-smoke cover MinIO separately), cross-process concurrency and true parallelism (single-threaded by design, no loom or shuttle anywhere in the workspace: grep of all Cargo.toml files), wall-clock effects, and process death (no crash mid-cycle; the in-process crash matrices carry that).

### Differential testing: oracles mostly real, two suites materially weaker

- PromQL vs real Prometheus (crates/ravel-promql-difftest): the strongest external oracle in the repo. Real Prometheus 3.13.1, sha256-pinned per platform, refused on placeholder digests (scripts/fetch-prometheus.sh:18-24, 81-108). 218 hand-written corpus entries across 10 files covering 131 constructs; 204 of 218 compare bit-exact on `f64::to_bits`, the 14 relaxations are ULP-bounded and refuse tolerance across zero, sign changes, or non-finites (src/comparator.rs:53-64, 85-93). Data reaches Prometheus over remote-write and Ravel through the production ingest router, so storage and eval are genuinely independent. An `expect: empty` verdict machine fails any construct whose evidence query silently returns no samples (src/scoring.rs:1979-2027) and a doc-drift job diffs the generated conformance table. Blind spots: the test is vacuous in the default workspace run (returns early without RAVEL_DIFFTEST=1, tests/difftest_selectors.rs:88-97) and only bites in the path-filtered `promql-difftest` job; one fixed seed and dataset (41 series, ~1.5k samples, one NaN payload, no denormals, no out-of-order or duplicate timestamps by generator invariant); 67 of 131 constructs rest on a single query; result order asserted for only 2 of 218 entries; three constructs (`unary`, `/`, `<`) have no corpus entry at all and are unit-test-only (src/scoring.rs:453-457, 577-590).
- SQL differential (crates/ravel-sql/tests/differential.rs): reference executor is hand-written Rust, not DataFusion, with the best value pool in the repo (three NaN payloads including negative NaN, -0.0, denormal, MIN_POSITIVE; tests/util/gate.rs:390-406) and hand-typed golden bit patterns as a second anchor (differential.rs:484-550). Shared-code blind spots: RSEG encode/decode and the `LabelMatcher` regex are shared with the SUT, so a joint bug there is invisible. flight_differential.rs is same-engine-both-sides by declared design (transport parity only). logs_differential.rs bypasses pruning for its reference but shares the RLOG record decoder and tokenizer; `Predicate::NumRange` is never generated so the numeric-range prune channel has zero differential coverage (its own doc comment warns about -0.0 and NaN bounds there).
- differential_compaction (crates/ravel-query/tests/differential_compaction.rs): the right three-way shape (L0 only, L1 plus lingering inputs, L1 only, all bit-equal, lines 287-322) against the real `compact_bucket`, with a checked-in proptest regression proving it caught a real NaN-payload-at-duplicate-ts case. Weaknesses: the dedup oracle is test-local and the production merge (`RsegDedupExec`/`merge_segments`) is never invoked; no fault injection at all; scalars only (no histograms through compaction); `Uuid::new_v4()` inside the property body (line 122) means the committed regression seed is not guaranteed to replay.
- OTLP vs OTAP (crates/ravel-otap/tests/differential.rs): mirror-drift catcher, but comparison is a set, not a multiset (`BTreeSet` projections at lines 339-348), so duplicate-point divergence and `is_monotonic_sum` divergence are invisible; exponential histograms diverge by design with no entry pinning the divergence shape; scalar values confined to -1000..1000.
- RW1 vs RW2 (crates/ravel-remote-write/tests/rw1_rw2_differential.rs): CONTRADICTED as meaningful coverage. The only property draws timestamps from `any::<i64>()` against a fixed ingest clock (lines 139, 250-253) whose admission window is roughly 4e-7 of the draw space, so in ~1,280 draws per run essentially nothing is ever admitted and the property verifies only that both decoders reject identically; nothing asserts a point was admitted; the comparison is derived `PartialEq` on `f64` (IEEE ==), so a -0.0 divergence is invisible and an admitted NaN would flake. Native histograms, exemplars, and metadata are never encoded on either side. No proptest-regressions file exists for it, consistent with never having caught anything.

### Property tests: generators mostly adversarial, five suites run far fewer CI cases than CI believes

- The float discipline claim (bit patterns, NaN payloads, -0.0 significant) is proven by property in at least five places, the strongest being arbitrary `u64` bit patterns through five codecs (crates/ravel-bench/tests/codec_roundtrip.rs:82-98) and explicit NaN-payload families (crates/ravel-codec/src/encoding.rs:1183-1195); dedup distinguishing -0.0 from 0.0 is proven against an independently reimplemented total-order oracle (crates/ravel-query/src/engine.rs:3035-3105, 3143-3151) and end to end through real segments and compaction. Thirteen proptest-regressions files are checked in with real shrunk counterexamples (NaN payload 18446744073709551615 at a duplicate timestamp, i64 extremes), direct evidence the properties catch bugs.
- Gap: no property carries NaN or -0.0 through `SegmentWriter::write_v4/v5/v7`; the writer properties clamp values to -1000..1000 (crates/ravel-segment/src/writer.rs:2817, 3951, 3981). Bit-exactness at the writer layer rests on hand vectors.
- Defect: `PROPTEST_CASES` is silently ignored wherever a suite pins `with_cases`, because proptest's `with_cases` resets from `Config::default()`, not the env-contextualized default. .github/workflows/ci.yml:386-390 sets `PROPTEST_CASES: 512` with a comment claiming CI "explores far more of the float edge-case ... space than a local run", but crates/ravel-sql/tests/differential.rs:209 pins 48 cases, flight_differential.rs:93 pins 24, logs_differential.rs:1104 pins 48, differential_compaction.rs:417 pins 24. CI runs 48 cases of the SQL differential, not 512. Two of my subagents verified the override semantics independently against the vendored proptest 1.11 source; I verified the ci.yml and test lines firsthand. The `fuzz` job's 4096 does work because those files set no config.
- Vacuous properties: crates/ravel-promql/src/eval.rs:3136-3159 contains the only two properties in the 3,100-line evaluator and both are assertion-free re-implementations of the expression under test whose overflow branch is unreachable from the generator range (secs < 1e9 cannot overflow i64 nanoseconds); crates/ravel-logseg/tests/corrupt.rs:256 is a single-valued-generator unit test re-run 600 times; crates/ravel-segment/src/writer.rs:2808's "mixed scalar/histogram" property only ever generates scalars.

### Golden, compatibility, corruption, fuzzing: current formats pinned, frozen contracts around them are not

- Golden-anchored: RSEG v7 whole-object byte pins plus a BLAKE3 pin for the 300 KB sparse object (crates/ravel-segment/tests/golden_bytes_v7.rs:386-437), RLOG v3 (crates/ravel-logseg/tests/golden_bytes_v3.rs:114-195), RSPAN v4 (crates/ravel-rspan/tests/golden_bytes_v4.rs:104-155). Old-version fixtures v1-v6 exist but are rejection seeds only; since readers are single-version by design, fail-closed rejection is the correct requirement and it is tested.
- NOT golden-anchored, all frozen contracts: commit token v2 (round-trip on a random UUID only, crates/ravel-types/src/lib.rs:695-708; negative parsing is pinned, the accepted encoding has zero external anchor, so a field reorder or base64-alphabet change passes every test while invalidating every client-held token); the commit record protobuf (round-trip only, crates/ravel-commit/src/record.rs:220); the catalog snapshot part/HEAD/postings (best-in-repo corrupt matrix of ~55 exact-typed-error cases in crates/ravel-catalog/tests/snapshot_format_corrupt.rs, yet no byte pin; the determinism proptests assert encode(x)==encode(x), which cannot catch drift); sys/gc; and no `buf breaking` or descriptor-set check guards proto field numbers anywhere in CI.
- Corruption assertion strength varies by format: crates/ravel-logseg/tests/corrupt.rs asserts no-wrong-data on both plain and pruned scans under truncate/flip/splice; crates/ravel-segment/tests/fuzz_mutation.rs's six properties assert no-panic only (`let _ =` bodies), never that a corrupt decode cannot return Ok with wrong values; crates/ravel-segment/tests/reader_v5.rs:500 is the only test anywhere that recomputes checksums after tampering, the one corruption class bit-flip fuzzing cannot produce; RLOG, RSPAN, and the catalog snapshot have no crc-refixed-tamper equivalent.
- cargo-fuzz: six libFuzzer targets exist (five in crates/ravel-segment/fuzz, one in crates/ravel-rspan/fuzz), all no-panic-only, detached from the workspace, with no checked-in corpus (gitignored) and no CI execution or even compile check (ci.yml:532 says nightly-only tooling is "deliberately not used"). They can bit-rot silently. The CI `fuzz` job is proptest mutation testing at 4096 cases over three targets, which is real but a different thing.
- The OTAP arrow-boundary panic is fixed in production: `StreamState::decode` wraps the arrow decoder in `catch_unwind` and returns a typed `BatchError::InternalPanic` (crates/ravel-otap/src/stream.rs:439-441), with a deliberately non-vacuous regression test that sweeps single-bit flips with no harness-side catch and asserts the typed-error count is positive (crates/ravel-otap/tests/decode_panic_caught.rs:1-18). The still-ignored `single_bit_flip_of_valid_ipc_can_panic_decoder` (tests/fuzz_mutation.rs:267) and that file's "known limitation" header are stale relative to the fix and would now fail if run.

### Concurrency testing: protocol races driven deterministically, no interleaving exploration

Races are tested at the protocol level with scripted sequencing: racing compactors resolved by CreateIfAbsent (crates/ravel-maintain/tests/crash_matrix.rs:174), folders racing the HEAD CAS (crates/ravel-failure-tests/tests/folder_crash_matrix.rs:297), pinned query racing the sweep (sweep_crash_matrix.rs:311), idempotency-marker write races (crates/ravel-ingest/src/idempotency.rs:490), cross-shard commit visibility and out-of-order multipart completion via hold gates (crates/ravel-failure-tests/tests/completion_ordering.rs), a 4-worker-thread producer/prober test for atomic flush visibility with a polls>0 vacuity guard (crates/ravel-failure-tests/tests/concurrent.rs:48-127), and real concurrent HTTP/gRPC requests held mid-flush for the shedding ceiling (services/ravel-server/tests/ingest_concurrency_e2e.rs). No loom, no shuttle (grep of every Cargo.toml). ADR-0068 rejects loom on the reasonable ground that the risky interleavings are protocol-level, but the promised protocol-level interleaving search is the unimplemented part above, so the net position is: races someone thought of are tested well; nothing searches for the ones nobody thought of. nextest runs with zero retries and no retry config anywhere (no nextest.toml exists), so flaky races are not being masked by retries, which is a genuine positive signal.

### Chaos, soak, Kubernetes: CONTRADICTED where claimed, one good artifact

- The chaos lane (scripts/chaos/) is dead code that has never executed successfully, while docs/adrs/0077-dr-posture-and-chaos-evidence.md is Accepted and describes its oracles as pinned. Four independent defects, the first three verified by me directly: (1) `metric_value` matches `$1 == name` exactly (scripts/chaos/lib.sh:398) but every metric it reads is rendered with labels (services/ravel-server/src/metrics.rs:706 emits `ravel_ingest_flushes_by_size_total{mode=...,signal=...}`; the server's own test at metrics.rs:4148 asserts the labeled form), so every metric read returns empty, the mid-flush kill trigger never fires, and all four scenario-2 oracles fail unconditionally; (2) scenario 1 queries `chaos_requests_total` (kill-ingest-flush.sh:41) while the fixture it drives emits `demo_requests_total` (services/ravel-server/examples/gen_otlp_fixture.rs:45), so strict-ack durability is reported violated for all 20 tokens; (3) commit tokens are base64 opaque strings but the harness regex-matches them as integers and computes `highest+1` (kill-ingest-flush.sh:137, lib.sh:591), making the no-partial-flush assertion pass for an unrelated reason; (4) scenario 2 generates load it never sends, so nothing is ever mid-compaction (kill-maintain-worker.sh:142-147). The lane is wired into no workflow and no recorded run exists; docs/guides/disaster-recovery.md:244-263 honestly records every rehearsal field as unrehearsed while also saying the lane's scripts do not exist yet (they do).
- No automated test anywhere kills a maintain worker mid-compaction and asserts sibling takeover: the takeover math is unit-tested as a pure function with a shrunk live-set vector (crates/ravel-fleet/src/worker_set.rs:598, :527), and the only two-real-worker e2e asserts a converged split, never a takeover (services/ravel-server/tests/maintain_ownership_metrics_e2e.rs:187).
- The one real, wired, assertive process-kill test is demo/kill-and-recover.sh (in CI at ci.yml:1518-1520): SIGKILL with exit-137 verification, new-container-ID check, per-run metric suffix so stale data cannot satisfy the query, and an explicit DATA LOSS verdict on an unsatisfiable token. It is single-container and path-gated, but it is the genuine article.
- Soak: zero hits repo-wide for soak/endurance/burn-in/overnight harnesses or records. The chaos lib even names a 24 h protection horizon and then explicitly declines to wait it out, deferring to "a separate long-run rehearsal" that does not exist (lib.sh:52, 754-767).
- Kubernetes: nightly kind pipeline deploys the operator, runs a store-qualify Job, applies one valid RavelCluster, and asserts one single-datapoint OTLP round trip with a strict-ack token and an exact value through separate gateway and query pods (scripts/kind-demo.sh:127-167). No pod kill, no load, no negative CRD apply (the CEL rules sit installed in a real API server and are asserted only against a hand-written Rust mirror, services/ravel-operator/src/crd.rs:1485-1493), replicas pinned to 1, and no envtest (documented as deliberate, services/ravel-operator/src/reconcile.rs:1-11). The same lane in PR CI requires a `run-k8s` label and `event_name == pull_request` (ci.yml:951-955), so the required `k8s-integration` check structurally never runs in the merge queue or on main push; nightly is the only real k8s signal and it has no failure routing (no issue filing, no artifacts), unlike quickstart-published.yml:183-232 which shows the repo knows how.

### CI: real gates with real holes

- What gates: 13 required checks per docs/adrs/0086 (lint, check, sql, flight-sql, features, supply-chain, fuzz, object-store-contract, promql-difftest, docker-build, actionlint, and more), nextest with zero retries, sql and flight-sql feature lanes with clippy unconditional and tests gated on `sql_area` (ci.yml:297-301, 384-435). The MinIO contract job and the difftest job both grep their own output to fail on silent skips (ci.yml:669-679, 906-915), which is unusually good.
- Holes: skipped required checks satisfy branch protection (documented at docs/adrs/0053:103-104), and the area classifier's catch-all only fires for `crates/`/`services/` paths, so a diff touching only Makefile, deny.toml, benchmarks/, or most of scripts/ leaves all four area flags false and silently skips sql, flight-sql, promql-difftest, object-store-contract, and bench-smoke (ci.yml:120-151). Four Docker-based e2e tests (Remote Write v1/v2 against real Prometheus, Flight SQL against MinIO, OTAP against a real collector) are `#[ignore]`d and no workflow passes `--run-ignored`, so they execute nowhere (services/ravel-server/tests/remote_write_prometheus_e2e.rs:219-225, flight_sql_e2e.rs:304, otap_collector_e2e.rs:243). `coverage` cannot block a merge yet fully determines the run conclusion the publish gate reads (self-documented at ADR-0086:415-421). sim-nightly and k8s-nightly file no issue and retain no artifact on failure. Floating image tags (`minio/minio:latest`, `floci/floci:latest`) sit inside required checks.

### Benchmark claims inventory: harnesses good, evidence absent

Classification of everything found (subagent inventory, key items verified by me):

- Microbenchmarks: 13 criterion targets across ravel-bench/segment/logseg/sql/otap/otlp/query. Synthetic. Never executed by any automation (`cargo bench` appears only in Makefile:71; no workflow runs it). No recorded results.
- Component benchmarks: catalog_resolve_bench, read-accounting bins, compaction_bench (reports object counts, bytes, wall, peak RSS; its L1<=80% size gate is explicitly report-only), groupby_scaling (the only harness in the repo that computes a standard deviation). Synthetic, MemoryStore, no recorded results.
- End-to-end: ingest_bench/s3_e2e_bench/bench_report measure ack p50/p95/p99 (strict mode explicitly), throughput, visibility lag, write amplification, PUT/GET/LIST counts, cold-vs-warm query (cold is a single observation, so its p50==p99). Synthetic, single tenant, MemoryStore by default on every bin.
- Production trace: NONE exists.
- Competitive: parquet_baseline (RSEG vs Parquet), codec bakeoffs, and a ClickBench port that is inputs-only ("it is the procedure, not a measurement", docs/guides/clickbench.md:8). No benchmark against Mimir/Loki/Tempo/Thanos exists despite README naming them architecturally.
- Committed measured numbers in the entire repo: one file of deterministic byte counts (crates/ravel-bench/tests/catalog_byte_gates_golden.txt) plus prose in ADRs. The bench output directory is gitignored (/bench/), and bench_report.rs:50-53's claim that CI treats bench/reports/ as committed evidence is false (no such path in any workflow filter). ADR-0070's designed performance gate (baselines under bench/baselines/, a bench_compare tool, +-15% advisory comparisons) does not exist; ADR-0070:41-44 itself states "nothing gates performance at all: a past eager-decode regression merged silently", and that remains true.
- The one public number: CHANGELOG.md:20-22 claims "an L1 object falls from 26.52 to 8.88 bytes per sample, a 2.99x reduction." Both numbers are the `random_float(ctrl)` arm (catalog_byte_gates_golden.txt:101, :110), which docs/adrs/0092 amends as "a worst-case control, not the representative cost" (representative arms are 2.50-3.00 bytes/sample, 8-10x). The error is in the conservative direction but the methodology is the one the ADR forbids. Verified firsthand.
- The only real-S3 lane (bench-s3.yml): weekly plus manual, skips green with no credentials, one 10-second workload at 1,000 series and a 500 ms flush cadence while the shipped production default is 2 s, artifact retained 90 days, no thresholds, no comparison.
- Missing dimensions with no measurement anywhere: cost per TB, cost per query, dollar cost against real S3 (explicitly deferred, docs/guides/cost-model.md:77-81), backlog recovery time, throttling/admission behavior under load, pod restart under load, compaction under concurrent load, cross-host network (every distributed panel is loopback and says so), large time ranges, multi-tenant load shape (every e2e core is one tenant; ADR-0070's planned --tenants flag does not exist). The most load-bearing number in the docs, ADR-0067's ~303k points/s MemoryStore vs ~1,285 points/s loopback MinIO (~236x collapse), exists only as ADR prose with no checked-in panel and no reproduction command. ADR-0036 already conceded the shape of this problem ("There is no S3/MinIO measurement anywhere in the repository") and mandates variance reporting for every benchmark (ADR-0036:126-127); one harness of ~14 complies.

## Failure scenarios

Concrete defects that ship while every suite above is green:

1. A regression in maintain-worker takeover (heartbeat staleness, unit re-ownership after a crash mid-compaction) ships: the pure-function tests pass, no e2e kills a worker, the chaos script that exists for exactly this cannot execute, and the nightly k8s lane never restarts a pod. First detection is a production incident.
2. Ingest throughput or ack-latency regression of any size ships: no benchmark runs in PR CI with a threshold, the weekly S3 lane has no comparison and can skip green, and the previous instance of exactly this ("a past eager-decode regression merged silently", ADR-0070:41-44) is documented.
3. A change to `CommitToken::encode` field order or alphabet ships green (round-trip test cannot see it) and invalidates every commit token clients hold; same class for the commit-record protobuf and catalog snapshot bytes (no golden, no buf-breaking gate). Detection is client-side read-your-write failures after deploy.
4. A divergence between the RW1 and RW2 decoders on admitted samples, on -0.0, or on native histograms ships: the differential's property never admits a point, compares with IEEE ==, and never encodes histograms.
5. An RSEG page corruption that keeps a valid checksum and decodes to wrong values would pass crates/ravel-segment/tests/fuzz_mutation.rs (no-panic-only) for every format except the one path reader_v5.rs:500 covers; for RLOG/RSPAN/catalog snapshots no crc-refixed-tamper test exists at all.
6. A float edge-case bug in the SQL differential space that manifests only beyond 48 random cases per run ships: CI's 512-case setting is inert, and everyone reading ci.yml believes otherwise.
7. A fault-handling bug on the fold write path or the query read path interacting with compaction timing ships: the sim never places faults there by design, and the hand matrices cover only enumerated rows.
8. A defect in any of the four Docker-gated e2e integrations (real Prometheus remote-write, real OTel collector OTAP, Flight SQL against MinIO) ships: those tests are ignored in every workflow.
9. An operator CRD CEL rule that drifts from its Rust mirror (rule text edited, mirror not) admits an invalid RavelCluster in production; no lane applies a violating spec against the real API server.
10. Orphan GC deletes restorable data during an incident: the documented breaker dilution/partial-restoration behavior is real (operator restores 6 of 55 records, the remaining 49 drop below the floor and are deleted before restoration completes), documented, and pinned by no test, so nothing stops a refactor from making it worse either.

## Severity-ranked findings

P1-1: No credible performance envelope; the suite cannot detect a performance regression and the one published number misquotes a control arm.
- Scenario: an ingest, query, or compaction performance regression of arbitrary size merges and ships; separately, an evaluator relies on CHANGELOG's 2.99x figure, which ADR-0092's own amendment reclassifies as a worst-case control (representative is 8-10x on realistic shapes, so here the error is conservative, but the quoting practice is exactly what the ADR forbids and next time the direction may flip).
- Evidence: only committed measurements are byte counts (catalog_byte_gates_golden.txt); /bench/ is gitignored; ADR-0070:41-44 states nothing gates performance and a past regression merged silently; bench-s3.yml:43-54 skips green without credentials, :86-92 one 10 s run at a 500 ms flush cadence vs the 2 s production default, artifact retention 90 days; CHANGELOG.md:20-22 vs catalog_byte_gates_golden.txt:101,110 vs ADR-0092 amendment (verified firsthand); ADR-0036:126-127 variance policy met by 1 of ~14 harnesses; ADR-0067's ~236x MemoryStore-to-MinIO collapse exists only as prose.
- Blast radius: production readiness assessment as a whole; every latency/throughput/cost expectation an operator forms from the docs.
- Probability/preconditions: certain over time; performance regressions are a base-rate event and nothing detects them.
- Workaround: run the existing harnesses manually against MinIO/S3 before any release; treat all doc numbers except byte counts as unverified.
- Recommended fix: implement ADR-0070 tier B as designed (committed baselines, bench_compare, advisory PR comparison); make bench-s3 fail red without credentials on scheduled runs; run it at the production flush cadence and commit the JSON report; correct CHANGELOG.md to the representative arms.
- Proof test: a CI job that compares bench_report JSON against a committed baseline and goes red on a seeded 20% ingest-throughput regression (inject a sleep in the flush path on a branch to prove the gate fires).

P1-2: Operational-resilience evidence is claimed but does not exist: the chaos lane is unrunnable dead code, no test kills a maintain worker, and there is zero soak evidence.
- Scenario: a takeover or crash-recovery regression in ravel-maintain ships; the documented DR rehearsal is attempted during an incident and the tooling itself fails; ADR-0077's Accepted status leads a reader to believe process-kill evidence exists.
- Evidence: scripts/chaos/lib.sh:398 label-blind metric parser vs services/ravel-server/src/metrics.rs:706/4148 labeled rendering (verified firsthand); kill-ingest-flush.sh:41 `chaos_requests_total` vs gen_otlp_fixture.rs:45 `demo_requests_total` (verified); kill-ingest-flush.sh:137 integer regex over base64 commit tokens (verified); kill-maintain-worker.sh:142-147 load generated but never sent; zero CI wiring for scripts/chaos (grep); docs/guides/disaster-recovery.md:244-263 all rehearsal fields unrehearsed; worker_set.rs:598 pure-function takeover test and maintain_ownership_metrics_e2e.rs:187 never killing a worker; zero soak hits repo-wide.
- Blast radius: durability and availability guarantees during real process death and multi-hour operation; RPO/RTO are unmeasured.
- Probability/preconditions: the evidence gap is certain (it exists now); the shipped-defect risk it hides is moderate because the in-process crash matrices are strong.
