B/page, B/sample: production INCLUDES the 6-byte RSEG page header
(enc/comp/crc); every other codec is raw codec output with no header.
ratio = codec bytes / production bytes, as measured.
ratio_hdr = codec bytes / (production bytes - 6), header-corrected.
dec Mts/s = median decoded millions of timestamps/s over 9 timed rounds,
1 thread. Production decodes a whole run (TS plus an all-zero VAL page)
through the public API, so its figure understates TS-only decode speed.
note: production's selected TS enc (1 TS_DELTA_VARINT, 2 TS_GCD_I64);
gcd = divisor the GCD codecs divided the page by.
dod_for = challenger (a): delta-of-delta, FOR-bit-packed per 128-sample block.
gcd_forced_dod = challenger (b): page / gcd, forced onto encode_i64's
double-delta arm alone (never its best-of search).
Rule, per row: a challenger is adopted only if bit-exact, ratio_hdr <= 0.75,
and dec Mts/s >= production's.

bytes/sample = codec payload (production excludes its 6-byte page header).
throughput = median Mval/s over repeated runs; production timings frame a whole
run (TS + VAL) through the public API, so they understate value-only speed.
'dec in MB/s' = INPUT-side, DERIVED: dec Mval/s scaled by the real compressed
byte count (challenger payload; production = compressed VAL page incl. 6-byte
header), not n*8. It folds in the compression ratio, so it restates columns
already on the row; read it only as the compressed-input rate.
'dec out MB/s' = OUTPUT-side: bytes the decoder writes, dec Mval/s * 8. Flat
across datasets and orders of magnitude below DRAM bandwidth (tens of GB/s),
so THIS is the evidence decode is CPU-bound, not memory-bandwidth-bound. All
throughput is single-threaded.
'ratio' = challenger bytes / production bytes; adoption needs <= 0.75 AND
dec >= production dec AND a bit-exact round trip.
cores (available_parallelism): 16   (throughput below is 1 thread)
